# @pyreon/validate

- **@pyreon/validate**:
  - Pyreon's `s` validator runtime + DX helpers on Standard Schema. `withField`/`getMeta`/`resolveMetaField`/`parseReactive`/`watchValid`/`formatErrors` (`parseReactiveAsync` supersedes stale in-flight results — an awaited stale frame resolves to the LATEST run's verdict). `s` runtime: primitives + object/array composition + modifiers + 20+ checks + object algebra (`.pick/.omit/.partial/.required/.extend/.merge/.keyof/.catchall`). ASYNC members (`.refine`/`.transform`/registered `.serverCheck`) work inside EVERY composition (union/DU/intersection/map/set/record/tuple + the JIT — a sync `parse()` of an async tree reports the ONE canonical "use parseAsync" issue at the root). `s.discriminatedUnion` accepts literal/enum/nativeEnum discriminants (dev-guarded: non-registrable field or duplicate tag throws at construction). **`.catch` runs against a PRIVATE child ctx** — a catch window can never eat a SIBLING field's issues (fuzz-found shared-ctx bug, both backends). `toJsonSchema(schema)` (subpath `@pyreon/validate/json-schema`) emits draft 2020-12 (input-shape contract; unrepresentable kinds throw or `{ unrepresentable: 'any' }`; cyclic lazy throws — no $defs in v1).
  - **Tree-shaking**: DX helpers tree-shake clean; the chainable `s.` API does NOT (prototype methods) — use `pyreon({ optimizeValidators: true })` to rewrite module-level `const X = s.<chain>` to the lean `@pyreon/validate/mini` form at build time (function chaining in, tree-shakeable output, parity-locked; ~−41% measured). `pyreon({ compileValidators: true })` inlines a monomorphic verdict for `.is()` (1.6–3.0× faster, nanoseconds — only matters in hot `.is()` loops). Both flags cover statically-analyzable chains within the emit slice (primitives + common checks + object/array/optional); out-of-slice chains gracefully stay full-runtime.
  - **Perf standings — RE-MEASURED 2026-08-31 against zod 4.5.4 / valibot 1.4.2 / arktype 2.2.3 / typebox 0.34.52 / yup 1.7.1 / joi 18.2.5. The headline changed: Zod 4.5 shipped `z.compile()` (a `new Function` codegen path) and a ~7.5×-faster failure path, so the old "fastest-or-CI-tied on all 12 cells; never behind" claim is FALSE and must not be restated.** The bench (`bench/validation.ts`) now runs TWO axes — `parse` (produce an output value) and `check` (boolean verdict) — over 6 libraries in 7 entries plus a `pyreon-legacy-is` control. TypeBox runs `check` only (no output-producing equivalent); Zod has no boolean-only API so its `check` cells are a full `safeParse` (both disclosed in the printed footer).
    - **`check` axis: fastest or 🤝 CI-tied on 10 of 12 cells** — outright wins on FLAT OBJECT (31ns, ahead of ArkType 35 / TypeBox 39), deep-nested (11ns) and object-with-array-of-objects (46ns); tied for first with TypeBox/ArkType/zod-compiled on number-range (both paths), flat-object invalid, array-of-20, deep-nested invalid, and DU (both paths). Both losses are `string.email` (ArkType ~1.2× ahead).
    - **`parse` invalid: outright win on EVERY shape** — 1.2–1.5× Valibot, 7.6–11.8× Zod (interpreted AND compiled), 12.3–37.0× ArkType, 18.7–138× Joi/Yup.
    - **`parse` valid: we are NOT ahead everywhere any more.** zod-compiled wins scalar number-range OUTRIGHT (3 vs 9ns); ArkType wins scalar-email (28 vs 34ns) + flat object (36 vs 50ns); array-of-20, object-array-of-objects, deep-nested and DU are all 🤝 CI-ties with zod-compiled. Ahead of interpreted Zod / Valibot / Yup / Joi on every valid shape. Residual causes: ArkType ALIASES the input (no clone) while Pyreon returns a stripped clone (deliberate semantic), and Pyreon's `Result` envelope is built by the `parse()` seam AROUND the generated function instead of inside it — pushing it into codegen is the identified next lever, NOT done.
  - **`.is()` has its OWN verdict-only JIT (2026-08)** — `tryCompileJitCheck`, a second emission from the same codegen: every failure site is a bare `return false`, the root returns `true`, no output value is constructed, no issue is allocated, and the emitted function takes ONLY the input (no ctx). Before this, `.is()` ran the PARSE validator and threw away both the issues and the strip-clone, which cost 5–33× vs TypeBox's `Check()` on invalid input. Measured as an in-run interleaved control: **1.2×–28.7×** (flat-object invalid 201→7ns, deep-nested invalid 139→7ns, DU invalid 84→8ns, array-of-20 valid 238→69ns). Shapes it cannot express — a `_runInto` fallback, or a check with neither an inline condition nor a `_pred` predicate (both need a real ctx to decide) — are REFUSED and `.is()` keeps the previous path. Locked by `jit-check-differential.test.ts` (contract: `is(x) === parse(x).ok`), which asserts PER-BLOCK how many schemas the verdict emitter actually served plus a fuzz coverage floor — otherwise a refusal makes the suite compare `parse` to itself and pass vacuously. Bisect-verified in five directions.
  - **Two measurement bugs were found and fixed in the harness itself; both invalidate any number taken before 2026-08-31.** (1) With one CONSTANT input per scenario the call is loop-invariant and V8 hoists it out of the timed loop — ArkType's `string.email` read ~3ns/op (below its own regex cost) while un-hoistable libraries reported their real ~28ns, i.e. the table ranked INLINABILITY. A result sink does NOT fix it; only rotating an input POOL does (now 8 same-shape different-value entries per scenario). (2) Running one library's 3 processes consecutively let a load burst land entirely on that library (a Pyreon cell read 155ns against its own 5ns) — processes are now ROUND-ROBINED across the libraries in a row, so contention widens every CI together and reads as a 🤝 tie. Also: the old "setup cost" table measured shared scenario construction (all nine columns ~1.4ms); it now reports only the explicit compile CALL (`z.compile` 15–72µs, `TypeCompiler.Compile` 11–55µs across the seven scenarios) and `—` for libraries that compile lazily or at definition time.
  - JIT architecture (unchanged, still the parse-path foundation): `tryCompileJit` recursively flattens pure object/array/primitive/DU shapes to one monomorphic `new Function` with static-path elision (`ctx.path` untouched on the valid path; issue paths reconstructed only at failure sites), async-aware fallback deferral, a memoized format resolver + `_pred` predicates so a format check costs one predicate call on the valid path, a lazy `EMPTY_PATH` sentinel (a scalar/flat-object parse allocates ZERO path arrays), a sync-only body when nothing can defer, DU-root compilation to a raw-value discriminant `switch` with member bodies inlined, and all-inline-primitive object bodies constructing their strip-clone as ONE object literal. A fully-inline tree is branded `_jitPure` and the public seams (`parse`/`~standard.validate`) reuse a per-schema ctx.
  - Locked by the JIT↔interpreter differential fuzz (now FIVE suites — incl. the verdict-JIT `is() ≡ parse().ok` suite — the DU suite covers NaN/enum/`__proto__`/fallback/async members + nested DUs) + `format-registry-routing` (the memoized resolver still swaps to the `/server` validator on install).
