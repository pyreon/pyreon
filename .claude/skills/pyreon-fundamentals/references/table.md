# @pyreon/table

- **@pyreon/table**: TanStack Table **v9** adapter — `useTable(() => opts)` returns the **`Table` INSTANCE directly** (no `Computed`, no `table()` call; options-as-FUNCTION so signal reads auto-track). The v8 accessor wrapper + version counter are GONE: v9 exposes a pluggable reactivity seam (`coreReactivityFeature`) and `pyreonReactivity()` backs its atoms with Pyreon signals, so `table.getRowModel()` read in any reactive scope subscribes natively. **v9 requires EXPLICIT feature registration** — build a `tableFeatures({...})` object ONCE at module scope (it is a compile-time type param) with only what you use; the core row model is automatic, the rest are slots: `rowSortingFeature`+`sortedRowModel: createSortedRowModel()`, `columnFilteringFeature`+`filteredRowModel`, `rowPaginationFeature`+`paginatedRowModel: createPaginatedRowModel()`, `columnVisibilityFeature` (**required for `row.getVisibleCells()`**), `rowSelectionFeature`, `globalFilteringFeature` (needs columnFiltering). `stockFeatures` = all 16 features but NOT the row models. Core types take a leading `TFeatures`: `ColumnDef<typeof features, T>`, `Table<TFeatures, T>`. `table.getState()` and top-level `onStateChange` are REMOVED → `table.store.state` / `table.atoms.<slice>` and per-slice `on<Slice>Change` (**supplying one puts that slice in CONTROLLED mode** — core stops self-updating it). Pinning is logical (`start`/`end`, not `left`/`right`); `sortingFn`→`sortFn`; `columnSizingInfo`→`columnResizing`; `getIsSomeRowsSelected()` now means "at least one" INCLUDING all. `flexRender` for column-def templates; **`flexRenderCell(table, rowId, columnId)`** is the fine-grained per-cell primitive — inside a keyed `<For>`, plain `flexRender(cell…, cell.getContext())` FREEZES on an in-place value change (the reconciler reuses the cell + never re-runs its body), so read cells via `<td>{() => flexRenderCell(table, row.id, cell.column.id)}</td>`. The adapter keeps **per-row version signals**: a cell subscribes to only its row, and the whole cell LOOKUP runs untracked (every v9 step — `getRowModel`/`getVisibleCells`/`getContext` — is a derived-atom read, so leaving any tracked re-subscribes the cell to table-wide state and coarse-invalidates everything). Structure/columns changes bump all rows (correct-by-over-invalidation); columns are compared by STRUCTURAL SIGNATURE, not array identity, because an inline `columns: [...]` literal churns its reference every sync. **Bench** (`bench:table` counts + `bench:table:wall`, both vs `@tanstack/react-table` wrapping the SAME table-core@9.0.0): single-cell edit re-runs **6 cell units / 1 DOM write** (only the changed row) = idiomatic memoized react-table (6) but with ZERO `React.memo` boilerplate and N-independent (verified at N=100 AND N=1000 on v9). Wall-clock figures (7-9× vs naive, ~1.1-1.2× vs hand-memoized, mount ~2× loss, sort ~2× vs memo-row) were measured on **v8 and have NOT been re-baselined on v9** — re-run `bench:table:wall` on an idle machine before quoting them. Honest loss that IS re-confirmed on v9: on a SORT the keyed path re-runs all cells (600/6000 units) where react-memo-row does 0 — coarse-but-correct, and the price of not requiring a user memo comparator. **Known limitation** (pre-existing, affects plain `flexRender` too): a data edit that changes the SORT ORDER updates cell VALUES but doesn't re-position keyed rows until the next structure/state change; `toggleSorting`/`setSorting` reorder normally. `.map()` over rows is the anti-pattern (full `<tbody>` rebuild). The runtime re-export list is now EXPLICIT/curated (not `export *`) so an upstream major is our migration rather than users'; `public-surface.test.ts` snapshot locks it.
