| `@pyreon/validation` | Universal, library-agnostic validation gate + **single canonical home for the Standard Schema contract**. - **@pyreon/store**:
  - `defineStore(id, setup)` — singleton by ID; auto-classifies setup returns (signals → state, functions → actions). `StoreApi<T>`: `.store`/`.state`/`patch()`/`subscribe()`/`onAction()`/`reset()`/`dispose()`.
  - **`setup()` runs in a store-OWNED `effectScope`** (Pinia model): setup/plugin `computed`s+`effect`s belong to the STORE — not adopted by the component whose mount first created it (pre-fix, that component's unmount silently froze the singleton's computeds for every other consumer) — and `dispose()` stops the scope (full teardown; no zombie effects on external signals). Plugins may return a cleanup fn → runs on `dispose()`.
  - Patch hot-path: the NO-subscriber object form writes signal fields directly (no event machinery); the WITH-subscriber object form takes a **detach fast path** — it suspends each patched field's internal change-detector for its own write (`@pyreon/reactivity`'s `_suspendSubscriber`/`_resumeSubscriber`, disposer-free `_s.delete`/`_s.add`) so the writes skip the batch-queue round-trip, then emits ONE mutation built directly from the written values (a re-entrant effect writing another store field during the drain is buffered + merged into the same notification). Field signals + a lazy `key→index` Map are cached at setup; the batch apply-closure + functional-form signal map are per-store cached (zero per-call closure allocs). Prefer per-field `store.x.set()` over bulk `patch()` for the tightest path. Dev warns on unknown patch keys and on same-id redefinition from a different setup (the HMR silent-stale shape).
  - **Persistence is composition, not middleware**: return `useStorage()` signals from setup — a StorageSignal IS a signal, so classification/patch/reset/subscribe/dehydrate all flow through it (cross-tab sync free). Store families = derived ids (`` defineStore(`doc:${id}`) ``); lifecycle manual by design.
  - **Schema-driven overload** `defineStore(id, { schema, initial, setup? })` (schema = a `@pyreon/validation` adapter OR any raw Standard Schema — a `zod`/`valibot`/`arktype` object passed DIRECTLY) — validates every write AND is **strictly typed from the schema** end-to-end: `SchemaStoreApi<TRaw, TStore>` infers field types via `InferSchema<S>` (which reads `_infer` for a Pyreon adapter, else `~standard.types.output` for a raw Standard Schema — the `types?`-optional form; a required-`types` match silently collapsed every raw schema to the loose fallback), so `state`/`set(next)`/`patch(partial)`/`deepPatch(DeepPartial)`/`update(key, current→next)` are all schema-typed with zero annotations (`update`'s key is constrained to field names; its transformer receives/returns `TRaw[K]`).
  - Escape hatches unvalidated by design: the functional `patch(fn)` form + direct `store.field.set(v)`. Async validators throw at definition-time.
- **@pyreon/state-tree**:
  - `model({ state })` or `model({ schema, initial? })` — chainable `.views()/.actions()/.volatile()/.lifecycle()` then `.create()` or `.asHook(id)`.
  - Schema mode is validation-driven AND strictly typed from the schema (pass `s.object()`/zod/valibot/arktype directly; installs bare-name `set/patch/deepPatch/update/reset` helpers that validate before writing).
  - `destroy()`/`isAlive()`, `clone()`/`getType()`, `getSnapshot()`/`applySnapshot()` (schema mode re-validates), `onPatch()`/`applyPatch()` (replace-only), `onSnapshot()` (microtask-coalesced), `onAction()`/`addMiddleware()`, tree traversal (`getParent`/`getRoot`/`getPath`), `identifier()`/`reference(Type)`/`resolveIdentifier()`.
  - Nested models compose in PLAIN mode; schema mode is flat.
- **@pyreon/form**:
  - `field()` + `useForm({ fields, onSubmit })` infers `FormState`. `useField('name')` (context), `<Form of={form}>`, `<Submit>` (auto-disables), `useFieldArray()` (stable `.key`, render with `<For by={i=>i.key}>`), `useWatch`/`useFormState`/`trigger`/`getValues`/`dirtyFields`/`touchedFields`/`getFieldState`.
  - **Auto-wired field a11y**: `register(field)` returns id + reactive `aria-invalid`/`aria-describedby` (+ `{ type: 'checkbox' }` → `checked`, `{ type: 'number' }` → `valueAsNumber`, `{ type: 'file' }` → value-less bag whose onInput writes the `FileList`); `errorProps`/`labelProps` give agreeing ids — zero hand-threaded ids, 0 re-renders.
  - **Focus-first-error**: a failed `handleSubmit` moves focus to the first errored + `register()`-bound field (`focusOnError`, default on — opt out `false`); `form.focusFirstError()` exposed for custom flows (SSR-safe).
  - `validateOn` default `'blur'`; async validators version-tracked; server errors via `setFieldError`/`setErrors` (don't touch `touched`).
  - `reset(values?, {keepErrors?/keepTouched?/keepDirty?/keepSubmitCount?})` (reset TO new values — named become the new baseline, rest revert to original) + `resetField(field, {keepError?/keepTouched?})`.
  - **`schema` accepts a plain `SchemaValidateFn`, a `@pyreon/validation` typed adapter (`zodSchema(...)`), OR a RAW Standard Schema (zod/valibot/arktype/`s`) directly — no adapter, no `as never` cast** (`resolveSchemaValidator` routes via `@pyreon/validation`'s `isStandardSchema`/`standardSchemaToValidator`; the `~standard` contract lives in validation — form depends on it). The `isStandardSchema` check runs BEFORE the bare-`function` → `SchemaValidateFn` fallback, so a CALLABLE Standard Schema (raw ArkType — `type(...)` returns a function carrying `~standard`) is detected as a schema, not mistaken for a hand-written validate-fn; a genuine hand-written function without `~standard` still hits the fallback.
  - **Schema-error routing (no silent drop) — auto-splits to the LEAF**: a schema error keyed by a dot-path (`address.city`, as the adapters flatten it) routes to the MOST-SPECIFIC registered field — the exact registered LEAF field `address.city` if present, else its nearest registered ancestor object field (`address`); a key matching NO field (typo / path-less `""` whole-form error) marks the form INVALID + sets `submitError` + dev-warns — never silently dropped (`matchSchemaErrorForField(schemaErrors, name, fieldNames)`/`orphanSchemaErrorKeys`). Both-registered (object `address` + leaf `address.city`) → the leaf wins, the ancestor no longer double-claims (dev-warns).
  - Keystroke path has NO per-field `effect()` (auto-validation driven inline from `setValue` reading `submitCount.peek()`); `values()`/`getValues()` epoch-cached.
  - **Dynamic fields**: `registerField(name, initial, validator?)` / `unregisterField(name)` add/remove fields at runtime (data-driven forms) — fully first-class (reach `values()`/`onSubmit`/validity); explicit escape hatch, still no *silent* auto-register.
  - **Dot-path leaf fields**: a field key with a dot (`'address.city'`) declares a FIRST-CLASS leaf field — `register`/`useField`/`setFieldValue`/`validators['address.city']`/`errors()['address.city']` all address it. Per-field validators + a FLAT-keyed schema (`s.object({ 'address.city': … })`) route their error to the exact leaf. **A REAL NESTED schema now auto-splits too**: a DECLARATIVE schema (raw Standard Schema / typed adapter — never a plain function) over a dot-path-leaf form receives the NESTED value shape (transiently rebuilt from the flat model via `nestValues`, so `s.object({ address: s.object({ city }) })` validates correctly), and its per-leaf-path errors (`address.city`) route to the registered LEAF field — else to the nearest registered ANCESTOR object field, else flagged as an orphan (never dropped). A plain `SchemaValidateFn` always receives the FLAT `TValues` (its type contract). The value model stays FLAT end-to-end (`values()`/`onSubmit` keep the dot-path keys → honest field-name types, no cascade); `nestValues(form.values())` / `flattenValues(serverData)` convert to/from a nested API payload. Declaring both an object field `address` AND a leaf `address.city` dev-warns (the leaf wins). Remaining gap: typed deep-path inference (`values()`/`onSubmit` + `schema` are typed against the flat dot-path keys, not a nested `NestValues<T>` shape — a nested declarative schema needs an `as never` cast today) — a tracked follow-up (its type cascade breaks generic wrappers like `@pyreon/feature`).
- **@pyreon/i18n**: `createI18n({ locale, messages, loader?, fallbackLocale?, ... })`. `t(key, values?)` — `{{name}}` interpolation, inline format specifiers (`{{amount, currency}}`), plurals (`_one`/`_other`/`_zero`), `context` (gender), `defaultValue`, `$t(key)` nesting (depth 4). Intl formatters on the instance: `n`/`d`/`rt` (read `locale()` reactively, memoized). Two entries: `@pyreon/i18n` (full + JSX `Trans`/`I18nProvider`/`useI18n`) and `@pyreon/i18n/core` (framework-agnostic). `<I18nProvider value={i18n}>` (prop is `value`); `<Trans i18nKey="…">` auto-reads `t` from context. `Intl.PluralRules` memoized per locale.
- **@pyreon/query**: full TanStack adapter — `useQuery`/`useMutation`/`useInfiniteQuery`/`useQueries`/`useSuspenseQuery` etc.; persist (`/persist` subpath) + devtools (`/devtools` subpath). **Options as a FUNCTION** (`useQuery(() => ({queryKey: [id()], ...}))`) so `queryKey` can read signals + refetch reactively; `useMutation` options are a plain object. `defineQueries({...})` named parallel queries. Fine-grained per-field signals, lazily materialized (slot-bag with property getters). Re-exports query-core (pinned tree-wide via `overrides`).
- **@pyreon/permissions**: `createPermissions(initial?)` callable as `can(key, ctx?)`; `can.not/all/any/assert/set/patch/clear`. **Wildcards (most-specific-first)**: `'posts.*'` = exactly one segment, `'posts.**'` = any depth below `posts`, `'*'` = everything; an exact/`**` deny overrides a broader grant (CASL `cannot`-over-`can` in flat-key idiom). Predicates `(ctx) => boolean` replace the MongoDB-condition DSL. `<PermissionsProvider value={can}>`.
- **@pyreon/table**: TanStack Table adapter — `useTable(() => opts)` returns `Computed<Table<T>>` (call `table()`; options-as-FUNCTION so signal reads auto-track). `flexRender` for column-def templates; **`flexRenderCell(table, rowId, columnId)`** is the fine-grained per-cell primitive — inside a keyed `<For>`, plain `flexRender(cell…, cell.getContext())` FREEZES on an in-place value change (the reconciler reuses the cell + never re-runs its body), so read cells via `<td>{() => flexRenderCell(table, row.id, cell.column.id)}</td>` passing the ACCESSOR (`table`, not `table()`). The adapter keeps ONE coarse version signal (drives the `<For>` structure) PLUS **per-row version signals** — a cell passed the accessor subscribes to only its row, so an in-place data edit re-runs just the changed rows' cells (state changes = sort/filter/selection/visibility bump all rows, coarse+correct for state-reading cells; distinguished from the spurious TanStack auto-reset onStateChange via a VALUE compare `sameTableState`, not reference). **Bench** (`bench:table` counts + `bench:table:wall`, both vs `@tanstack/react-table` wrapping the SAME table-core@8.21.3): single-cell edit re-runs **6 cell units** (only the changed row) = idiomatic memoized react-table (6) but with ZERO `React.memo` boilerplate and N-independent; wall-clock **7-9× faster than naive react-table, ~1.1-1.2× faster than hand-memoized** (N=100/1000). The wall bench's Pyreon fixture compiles through the REAL `transformJSX` (`pyr-tpl` — what vite-plugin apps ship, the verdict baseline; the hand-`h()` path stays as a transparency column) and every cell carries an untimed real-DOM correctness gate. Honest losses (disclosed, fine-grained mount tax + coarse-on-state): mount ~2× / replace ~1.1-1.3× (per-cell reactive-binding setup — MEASURED as the true cause: the compiled fixture closes only ~10% of the mount gap, so it's the price of the per-cell subscriptions buying the update wins, NOT an h() harness handicap as previously attributed), sort ~2× vs memo-row (coarse re-runs all cells; react-memo does 0 but needs the user's memo comparator; vs NAIVE react, sort is 🤝 tied). Sibling verdict in `@pyreon/virtual`'s bench (same treatment): steady-state scroll **1.3× faster** than react-virtual on the compiled path, fixed-size mount 1.1× slower (one-time ~16µs on a 10k list — same binding-setup class), `item()` dynamic mount 1.3× the fixed mount (per-row signal tax, amortized by the scroll/remeasure wins). **Known limitation** (pre-existing base-adapter, affects plain `flexRender` too): a data edit that changes the SORT ORDER updates cell VALUES but doesn't re-position the keyed rows until the next structure/state change — `getSortedRowModel`+`<For>`+version-bump timing; `toggleSorting`/`setSorting` reorder normally. `.map()` over rows is the anti-pattern (full `<tbody>` rebuild). Re-exports all table-core; `public-surface.test.ts` snapshot locks the export set.
- **@pyreon/machine**: `createMachine({ initial, states })` — `machine()` reads, `machine.send(event, payload?)` returns settled state, `matches`/`can`/`nextEvents`/`isFinal`. Guards `{ target, guard }` (throw-safe → denied); `can()` predicts `send()` exactly. Eventless `always` transitions (fire synchronously, cascade, self-loop throws after 1000). Final states + `onDone`; lifecycle `onEnter`/`onExit`/`onTransition`. Out of scope vs XState (offloaded to signals/effects): context, invoked actors, hierarchical/parallel states, delayed `after`.
- **@pyreon/flow**:
  - `createFlow<TData>({ nodes, edges })` / `useFlow<TData>()` (auto-disposes). Node/edge CRUD, selection, viewport. Components `<Flow nodeTypes>`, `<Background>`, `<MiniMap>`, `<Controls>`, `<Handle>`, `<Panel>`.
  - Configurable edge markers (`MarkerType.Arrow`/`ArrowClosed`, per-edge `markerStart`/`markerEnd`). **Default marker = small filled arrowhead in the LINE colour** (`DEFAULT_MARKER_COLOR` is `var(--pyreon-flow-edge, #999)`, applied via `style` since `var()` is invalid in an SVG presentation attr) so an unstyled arrow reads as a continuation of its line + re-themes with it; the glyph uses `markerUnits="userSpaceOnUse"` so its px size is independent of the (1.5px) edge stroke — width is literal px, not `strokeWidth`-scaled. `markerId` sanitizes the var to a stable dedup token distinct from an explicit `#999`. Render virtualization (`onlyRenderVisibleElements`, default off); object-snapping opt-out (`snapToObjects`, default on — O(N)/frame).
  - Custom node/edge renderers get reactive accessors; each node mounts EXACTLY ONCE; drag writes the `nodes()` array → O(N)/frame via `nodeMap`/`edgeMap` computeds (NOT O(N²)).
  - **Edge rendering (three coupled invariants — all three needed for edges to VISUALLY render, see anti-patterns "zero-area svg viewport"):** (1) the `.pyreon-flow-viewport` div is sized `width/height: 100%` — a 0×0 viewport collapses the edge `<svg width:100%>` to 0×0, which paints NOTHING (edge `<path>`s exist in the DOM with valid geometry but never render — the paint bug the app-showcase path-COUNT e2e masked). (2) That full-size transformed viewport is `pointer-events: none`; node wrappers re-enable with `pointer-events: auto`, edge paths with `pointer-events: stroke` — else it swallows Controls/MiniMap/pan clicks. (3) **Node auto-measurement**: a per-node `ResizeObserver` writes the rendered size AND every `<Handle>` dot's center to `instance.measurements` (a `Signal<Map<id, NodeMeasurement>>`). **The ONE effective-dimensions rule** (`getEffectiveDimensions`: explicit `width`/`height` → measured → 150×40) drives EVERY geometry consumer — edge anchors, `layout()` (ELK gets real boxes), `fitView`, snap lines, rubber-band hit-tests, minimap, `<NodeResizer>` baseline, viewport culling — via `flow.getNodeDimensions(id)` / the internal `nodeDims`. Measurement is client-only (SSR/happy-dom report offsetWidth 0 → falls back to explicit-or-default).
  - **Edge anchoring priority** (`edges.ts:resolveHandleAnchor`, per endpoint): `edge.sourceHandle`/`targetHandle` → MEASURED `<Handle>` dot center (pixel-exact, wherever CSS placed it; dot centers recorded node-relative/unscaled via gBCR÷zoom — offsetLeft is unusable, a custom node's own `position:relative` re-bases it) → config handle side-midpoint → first handle of the type → null → **floating endpoints** (`getFloatingEndpoints`/`getNodeIntersection`: connect where the center-to-center line crosses the perimeter — natural-angle arrows, React Flow's floating-edge model). Unknown handle id anchors at the first handle + dev-warns ONCE naming known ids. The live connection-draw line starts at the measured dot too.
  - **Edge modes/tunables**: per-edge `pathOptions` (`curvature` → bezier, `borderRadius`+`offset` → smoothstep, `offset` → step) threaded through `getEdgePath`; `config.defaultEdgeOptions` merges flow-wide edge defaults at normalize (initial + `addEdge` + drawn connections; per-edge values incl. explicit `markerEnd: null` win; type chain `edge.type` → `defaultEdgeOptions.type` → `defaultEdgeType`).
  - **Theming is COMPLETE via `--pyreon-flow-*` vars** (25, all with light fallbacks — nodes/edges/handles/controls/minimap/toolbar/resizer/selection; documented table in docs "Theming"); SVG colors always via `style`, never presentation attrs (`var()` invalid there).
  - The container pan `pointerdown` bails on `.pyreon-flow-controls/-minimap/-panel/.nodrag/button/…` (not just nodes/handles) — otherwise `setPointerCapture` eats the button's click and the zoom/fit buttons do nothing.
  - Overlay child order (compiler ref-hoist — see anti-patterns): `<Controls>`/`<MiniMap>` order no longer matters on current compilers; apps pinned to older compilers still need `<MiniMap>` BEFORE `<Controls>`.
  - **The package's vitest-browser tests now run through the REAL `@pyreon/vite-plugin` compiler** (`vitest.browser.config.ts` adds `pyreon()`; `@pyreon/vite-plugin` is a flow devDep) — they exercise the shipped `_tpl()` template path, closing the historical "wrong-transform masks template bugs" trap FOR THIS PACKAGE (verified with a `_tpl(`-presence probe plugin + negative control). Other packages' vitest-browser suites may still use the default transform — check before trusting them for template-emission claims; real-compiler e2e remains the cross-package gate.
  - `dev` gate uses bare `process.env.NODE_ENV` (reference `layout.ts:warnIgnoredOptions`). Peer dep `@pyreon/runtime-dom`.
