# Pyreon Multiplatform (PMTC)

> Extracted verbatim from CLAUDE.md. This is the authoritative copy — edit it here.

The Pyreon Multi-Target Compiler emits SwiftUI + Compose from one `.tsx` source. **Scope the "100%" precisely**: what's done is the **emit vocabulary** (all 15 canonical primitives map to both targets). It does NOT mean "all packages work on native," "device-proven," or "production-ready" (demo-quality; the ONE authoritative score is the gated capability matrix in `docs/src/content/docs/multiplatform.md` — `check-multiplatform-matrix` recomputes it from the table, so never quote a number from memory). Three reality-checks:

- (a) **PMTC compiles a declarative TS subset; the failure mode outside it is now MOSTLY a NAMED warning, not a silent drop** — the current per-PR-maintained closed/open construct list lives in `docs/multiplatform.md` (do NOT re-enumerate it here; an inline list drifts stale). Verified LOWERING + `swiftc`/`kotlinc`-typechecking on both real toolchains: local object/array literals, destructuring, `Map`/`Set`, common control flow, template literals, optional chaining, fractional math, and string/array methods. Constructs still OUT of the subset now WARN by name (`enum`/`class`, GENERIC-or-`extends` `interface`, `try`/`throw`, JSX spread on a primitive, regex literals, `JSON.parse` — but `JSON.stringify(x)` now LOWERS: Swift `JSONEncoder().encode`, Kotlin `Json.encodeToString`, since emitted structs are Codable/@Serializable; `JSON.parse` stays warned because it throws, which needs the native error model `try`/`throw` still lacks — computed object keys, call-arg spreads, top-level helper functions) — a top-level OBJECT-SHAPE `interface X { … }` is now SYNTHESIZED into a struct/data-class (same as a `type X = { … }` alias; `parse.ts:tryStructFromInterface`). Genuine remaining gaps: generics in logic, and nested/edge shapes outside the tested corpus — see `docs/multiplatform.md` for the live per-construct status (esp. the helper-function arc, which is moving from warn → native emit). **The load-bearing caveat is now PARTLY closed on the Swift side**: the per-PR gate was `swiftc -parse` (syntax-only, NOT typecheck) + `kotlinc`-against-stubs — so a Swift TYPE-level corruption (the `.animation(_:value:)`-needs-`Equatable` class that shipped the M2.8 incident) was invisible per-PR, caught only days later by the advisory device gate. As of M-gate.1 there is a per-PR `swiftc -typecheck`-against-STUBS gate too — `validateSwiftWithStubs` (validate.ts) + `swift-stubs.ts` (the Swift sibling of `kotlin-stubs.ts`): it strips the emit's `import SwiftUI`/`PyreonRuntime`/`PyreonRouter`, concatenates a minimal stub whose generic constraints mirror SwiftUI EXACTLY (`animation<V: Equatable>` — a loose `value: Any` would MASK), and type-checks on the plain Linux runner (no Apple SDK). It runs in the existing `Validate emitted Swift + Kotlin` job (rides `bun run --filter='@pyreon/native-compiler' test` under `PYREON_REQUIRE_NATIVE_VALIDATE=1`, zero YAML change) and is bisect-locked (`validate-swift-typecheck.test.ts`: revert the emit's `.count` fix → RED with the exact `Todo conform to Equatable`; `-parse` PASSES the broken emit). M-gate.1b expanded the stub to **27 of 37 compiler fixtures** (+ the 2 example apps) — the canonical primitives, common SwiftUI modifiers (`.font`/`.frame`/`.padding`/`.opacity`/`.bold`/`.sheet`/`.onAppear`/…), and the cheap PyreonRuntime types (i18n/machine/permissions/link/webview) — and added a **shadow-strip mechanism** (validateSwiftWithStubs drops any stub type the emit itself declares, so a user component named after a SwiftUI type — e.g. `Toggle` — doesn't false-`invalid redeclaration`; a real multi-module build shadows it) plus `@ViewBuilder`-on-the-requirement support for bare-`if` component bodies. **M-gate.1c then FIXED the first REAL emitter bugs the gate surfaced (gate now 30/37)** — the gate earning its keep by driving fixes that make emitted native code actually COMPILE: (1) rx scalar-accessors `rx.first`/`.last`/`.find`/`.min`/`.max` now infer an OPTIONAL binding type + `rx.average` infers `Double` (`infer-type.ts` rx-call case — they emitted `.first`/`.min()` (Optional) into a NON-optional `var x: T { … }` = uncompilable), and (2) a null-returning component now emits `EmptyView()` (Swift) / an empty body (Kotlin), not the uncompilable `var body: some View { nil }` (`emitSwiftReturnExpr`/`emit-kotlin`). Both bisect-locked; rx-full/rx-lowering/tier2-machine moved into the gate corpus. Residual (tracked follow-ups): the **service-runtime + `@Observable` surface** (`PyreonRouter`/`RouterProvider`/`useNavigate`/`useParams`/`PyreonStoreProtocol`/`PyreonModelProtocol`/`PyreonForm`/`PyreonAuth`/`PyreonDatabase`/`PyreonFetch` + the `@Observable` macro, which a struct stub can't fake) covering 6 heavy fixtures, and `tier2-rx`'s `interface Todo` not being synthesized into a `struct` (`interface` is a warned out-of-subset construct — a distinct frontier expansion). Plus the real-SwiftUI `-typecheck` gate, which now runs PER-PR IN CI (advisory): the `validate-swift-typecheck` macOS job in `native-validate.yml` runs the native-compiler suite on a macOS runner where `isSwiftUIAvailable()` is true, so the ~58 `it.skipIf(!isSwiftUIAvailable())` REAL-SDK `swiftc -typecheck` blocks EXECUTE (they SKIP on the ubuntu `validate` job — Linux swift has no SwiftUI). Its delta OVER the stub gate is INCREMENTAL, not from-scratch: the mirror stubs already catch most type corruption on Linux, so the real-SDK cell adds stub-MASKING insurance (a real-SDK-only type error the mirror stub doesn't model) + the `@Observable`/Observation surface a struct stub can't fake. It does NOT close the heavy PyreonRuntime-service fixtures (same `-I` scope limit as `validateSwiftTypecheck` itself — a tracked follow-up). Advisory-first (promote to required once macOS-image drift is proven stable). Plus the advisory device gate.
- (b) **Device proof is REQUIRED**: `iOS — xcodebuild (Simulator SDK)` + `Android — gradlew assembleDebug` (native-device.yml) AND `Validate emitted Swift (real-SDK typecheck, macOS)` are branch-protection required checks (API-verified 2026-08-03) — a native-touching PR cannot merge without building + running its UI assertions on a real Simulator/Emulator. Coverage caveat: only the GATED example apps get that treatment; a capability no gated app exercises ships on stub-typecheck strength.
- (c) **Rich web packages (flow/charts/code/dnd/document/query/table/virtual + the CSS-in-JS ui-system) are web-only by architecture** — PMTC compiles your source, not npm libraries.

**Four-layer shared-code model**:

- L0 `signal()/computed()/effect()` (runs identically; maps to `@State`/`mutableStateOf`);
- L1 custom pure-logic hooks (100% shared);
- L2 ServiceBackend hooks (`useStorage`/`useRouter`/`useFetch`/`usePermissions`);
- L3a `@pyreon/primitives` (15 canonical multi-platform primitives — `Stack`, `Inline`, `Layer`, `Scroll`, `Spacer`, `Text`, `Heading`, `Image`, `Icon`, `Button`, `Press`, `Link`, `Field`, `Toggle`, `Modal`; one canonical name per concept, `onPress` everywhere, tokens-first styling, no responsive/animations in v1);
- L3b `@pyreon/elements` (web-only-rich, rocketstyle/styler-coupled);
- L4 `<NativeIOS>`/`<NativeAndroid>`/`<Web>` escape hatches.

Canonical primitive maps: `packages/native/compiler/src/canonical-primitives.ts` (`SWIFT_NAMES`/`KOTLIN_NAMES`, 15 each). Cross-platform a11y vocab (`AccessibilityProps`): `accessibilityLabel`/`accessibilityHidden` lower per-target on ALL THREE targets — web (`aria-label`/`aria-hidden`), iOS (`.accessibilityLabel(...)`/`.accessibilityHidden(true)`), Android (`semantics { contentDescription }`/`clearAndSetSemantics {}`); emit R2-locked in `canonical-primitives.test.ts`. `accessibilityLabel` is iOS-DEVICE-PROVEN (native-counter XCUITest asserts a labelled element is queryable by its label, not its visible glyph — first R4 of an a11y lowering). `accessibilityHidden` stays R2: XCUITest string queries don't reliably reflect `.accessibilityHidden(true)` (tooling limitation, not an emit gap).

**Per-platform import resolution**: on web `@pyreon/primitives` runs the real DOM impl; on iOS/Android the PMTC compiler intercepts the JSX and emits native code before the runtime — the import is type-anchor-only.

**Native runtime ports** (`packages/native/runtime-{swift,kotlin}/`): storage (`@PyreonAppStorage`/`rememberPyreonStorage`), forms, fetch, permissions, router (`PyreonRouter` + guards + nested routes + per-route loaders), plus Phase-5 hooks (`useAuth`/`useDatabase`/`useGeolocation`/`useMap`/`useWebSocket`/`usePush`/`usePayments`).

**Lifecycle auto-start** — PARTIAL (not "none"):

- `useFetch` (auto-fetch) + `useWebSocket` (auto-connect) + `onMount(fn)` sync bodies ARE synthesized on mount on BOTH targets with NO explicit `.begin()`/`.connect()` call needed (Swift `.task`/`.onAppear` on a stable-identity ZStack host, Kotlin `LaunchedEffect(Unit)`).
- The remaining service hooks (`useGeolocation`/`usePush`/`usePayments`) are NOT yet auto-started — their Kotlin `start(register:)`/`connect(register:)` needs a default per-hook transport first (the SAME OkHttp-for-WebSocket asymmetry: Swift's `PyreonGeolocation.start()` is 0-arg, Kotlin's takes a host closure), so call `.start()`/`.connect()` from an effect for those.
- `useDatabase`/`useMap` need no start (ready-on-init); `useAuth.beginSignIn()` is user-triggered. `useSecureStorage` deferred.

**Native lifecycle gotchas (device-found, compile-only can't catch)**:

- (1) `<Suspense>`/`<ErrorBoundary>` compile to an INLINE conditional read in the component body (the `@Observable`/recomposition read must be in `body` to be tracked — wrapper-struct arg-passing does NOT track).
- (2) Swift `.task` needs a STABLE-identity host — a fetch-bearing component's body is wrapped in a concrete `ZStack` so `.task` fires once (attached to a transparent `Group{if…}`, SwiftUI redistributes it onto the branch and cancels+restarts per flip → fetch thrashes forever); Kotlin uses a `LaunchedEffect(Unit)` sibling, no equivalent needed.
- (3) **`<Inline>` is a non-wrapping Compose Row (overflows) but a shrinking SwiftUI HStack** — a horizontal group that fits on iOS can clip its last children off-screen on Android; stack vertically or keep groups narrow; treat "tap works on iOS, times out on Android" as Row-overflow first.
