# @pyreon/code

- **@pyreon/code**:
  - `createEditor({ value, language, theme, ... })` — `value` is writable `Signal<string>`; `cursor`/`selection`/`lineCount` computed; `<CodeEditor>`/`<DiffEditor>`/`<TabbedEditor>` (user-owned lifecycle — call `editor.dispose()`). `bindEditorToSignal({ editor, signal, serialize, parse, onParseError? })` two-way.
  - CodeMirror 6. 19 lazy language grammars — 17 via `@codemirror/lang-*`, `ruby`+`shell` via `@codemirror/legacy-modes` (`StreamLanguage`, optionalDependency); only `plain` is empty. `createTabbedEditor` is exported. **Measured bundle** (esbuild+gzip+code-split, `bun run --filter=@pyreon/code bench`): core editor ~138KB gz (~416KB min, framework external, no grammar), at parity with `@uiw/react-codemirror` (~129KB gz); each grammar a ~40KB gz lazy chunk reusing the loaded core; Monaco ESM core ~940KB gz (~3.6MB min, workers/CSS excluded) → ~7x smaller gz, NOT the old "~250KB vs ~2.5MB / 10x" claim (a bundle-size bench, not runtime latency).
  - `onError` config surfaces mount failures (a throwing extension / failed grammar import) instead of an unhandled rejection; dispose-during-async-mount is leak-safe (`mountToken` guard); `<DiffEditor>` unmount-during-load is leak-safe (`unmounted` guard). Peer dep `@pyreon/runtime-dom`.
  - **`foldAll`/`unfoldAll` are STATIC imports from `@codemirror/language`** — a prior `require('@codemirror/language')` threw `require is not defined` in every ESM browser bundle (`type: module`). Minimap dark/light detection reads `view.state.facet(EditorView.darkTheme)`, NOT a `cm-dark` class (CM6 uses hashed style-mod classes — the class check never matched, so a dark editor always got a light minimap). Both were browser-only bugs invisible to happy-dom + the no-view unit tests; locked by `code.browser.test.tsx`.
