# CI architecture

Read before adding or changing a workflow, job, required check, or cache key.

the org is on GitHub's FREE plan: **20 concurrent jobs org-wide, 5 macOS**, shared by every parallel session's PR. On a public repo runner-minutes are unmetered; SLOTS and DAG LEVELS are the whole constraint. Re-measured 2026-09-01 (the 2026-07 figures were 4× stale): an ordinary code PR (run 33544139801) produced ~45 check-runs across 9 workflows and spent **641 min queued for 24 min of work (27×), 90 min wall**; a docs-only PR waited 48 min for 5 min of work; four aggregator jobs each sat ~50 min in queue to run for 2 s. So the design rule is: **a gate that takes seconds is a STEP, never a job**, and the graph is two levels deep. `ci.yml` is 13 jobs (was 29 + 6 standalone workflows): level 1 = `Install` (install → decide → build `lib/`, ONE job with one failure semantics; its outputs `code` / `affected` / the batched `typecheck-` / `test-` / `e2e-` / `scaffold-matrix` gate everything else, all fail-closed — a detection error runs the full set because a skipped required check reports SUCCESS to branch protection); level 2 = `Fast Gates` (every lib-free gate: lint, ratchets, docs sync, manifests, export entries, release readiness, doc examples, dependency audit, secrets scan, PR-targets-main), `Build` (every lib-needing gate: examples build, verify-modes, bundle + import budgets, distribution, bin liveness, coverage floor + changed-packages, the Rust-binary equivalence run), the dynamic cells, `Test (browser)`, `Release Build`, `bootstrap-exit-codes`; level 3 = `Test`, the ONE aggregator for all four matrices. Every gate step inside Fast Gates / Build runs even after an earlier step failed (`!cancelled()`), so one push reports every red gate. Label-sensitive gates (`Changeset`, `Diagnose Catalog`) live in `pr-gates.yml` because ci.yml's `pull_request` trigger deliberately excludes `labeled` (a label would cancel the in-flight run). **Lib-free vs lib-needing**: typecheck/lint/vitest resolve `@pyreon/*` to `src` via the bun condition and do not need `lib/`; EXCEPTION = tests that assert on `lib/` bytes or boot a nested Vite SSR build — a new lib-needing gate goes into `Build`, a lib-free one into `Fast Gates`, and a NEW JOB needs a written reason it cannot be a step. Branch protection pins **15 required contexts in TWO authorities — classic protection AND ruleset 19416270, kept identical** (`Install`, `Fast Gates`, `Build`, `Test`, `Test (browser)`, `Release Build`, `bootstrap-exit-codes`, `Changeset`, `Diagnose Catalog`, `Analyze (javascript-typescript)`, `CodeQL`, the two `Validate emitted Swift…` jobs, `iOS — xcodebuild`, `Android — gradlew`). NEVER rename a required job; DROP a name from both authorities before deleting its job (a dropped name can never block), never ADD one (an added name hangs every open PR on "Expected" until its next push). Cache discipline: one artifact ⇒ one key prefix ⇒ one writer (`bun-install-cache-*` is saved by Install on main only; everyone else restores) — the 10 GB actions cache hit capacity three times from duplicate writers, evicting the small entries every PR needs; small content-addressed stores (the native verdict store) are saved from EVERY run because main's push run is cancelled 27/60 times. **Conflicting PRs do not get to hold slots**: GitHub refuses to DISPATCH a `pull_request` workflow for a conflicting PR (the merge ref cannot be built — the "checks never started" trap), but it does NOT stop a run already in flight when a merge to main creates the conflict; that run tests `old-main + head`, cannot merge, and is superseded by the fresh run the conflict-resolving push will dispatch. `cancel-conflicting-ci.yml` (push:main + every 30 min) sweeps them — measured 2026-09-02, **169 of 254 in-flight runs (66%) belonged to PRs that could not merge**, ~189 jobs against a 20-slot cap. It is fail-safe by construction: only a DEFINITIVE `CONFLICTING` is acted on, `UNKNOWN` (what GitHub answers for every PR right after a base push, while it computes lazily) is skipped, and a failed listing aborts rather than proceeding with an empty conflict set. **Re-measured 2026-09-07 (25 PR runs): a code PR is 21 ci.yml jobs, 36–65 min of summed work, 300–620 min of summed queue, 31–48 min wall — ~38 runnable jobs across 9 workflows.** The largest single tenant was the NATIVE lanes (~45 of ~115 Linux slot-min and ~95 macOS-min per PR), and they fired on every dual-backend compiler PR because both decide regexes matched the JSX compiler's napi crate (`packages/core/compiler/native/`) and EVERY `package.json`; the macOS real-SDK typecheck lane also had NO verdict cache (36–58 min cold on every run while its Linux twin restored one). Fixed: ONE fail-closed classifier (`scripts/native-surface-touched.ts`) feeds both decides, the macOS lane restores/saves the content-addressed verdict store, the two macOS jobs restore the bun tarball store (UNMEASURED until the nightly seeds it — on Linux the same restore was measured a net LOSS: 56 s to restore 2 GB, download+link 58→78 s, because the install's ~100 s is the postinstall lib/ bootstrap, which no download cache helps), and `cancel-conflicting-ci.yml` prunes SUPERSEDED cache generations on main every 30 min (`scripts/prune-superseded-caches.ts` — 5.8 GB of a 9.9 GB budget were dead copies; at capacity GitHub evicts the small verdict store first, which is what turns a 1-min native cell into a 25-min timeout-cancel). Cell packing (e2e 4→2, scaffold 3→2, typecheck 3→2) was priced and DECLINED: a cell's fixed setup is ~1 min, so packing buys 1–2 slot-min per lane while lengthening the critical path. Diagnostic recipe in `.claude/rules/workflow.md` (per-job `created_at`→`started_at` = queue, `started_at`→`completed_at` = work; EXCLUDE `skipped` jobs). `scripts/affected.ts` computes the per-PR filter (root-file change → `--filter=*`); `scripts/ci-batch.ts` packs cells (LPT by measured weight). E2E is a flake-resilient parallel matrix (`retries: 2` in CI). `scripts/bootstrap.ts` env: `PYREON_BOOTSTRAP_SKIP` / `_SKIP_NATIVE` / `_SOFT` / `_FORCE_FAIL`.

## Gate reference

- **audit-types** (`bun run audit-types --all --strict`, CI required): flags public-interface fields with zero non-type refs (typed-but-unimplemented). New HIGH findings block; triage = fix the runtime or add to `EXEMPT_FIELDS` with rationale.
- **verify-modes** (`bun run verify-modes`, CI required): `vite build` every example × mode cell, asserts rendered CONTENT (not just a green build). Add cells that verify content, not build success.
- **check-bundle-budgets** / **check-import-budgets**: gzipped main-entry + canonical-minimal-import size vs locked budgets (`scripts/{bundle,import}-budgets.json`; measured against built `lib/` with `NODE_ENV=production` define + AST-collected externals). Growth intentional → `--update` + review diff.
- **check-distribution**: every published pkg declares `sideEffects`, ships source maps, and excludes the `lib/analysis` bundle report (live `npm pack --dry-run` probe).
- **check-esm-only**: Pyreon ships **ESM and only ESM**. No CommonJS build, and no export condition that lets a CJS resolver load us — `require` and `default` are BOTH banned in every published package's `exports`. The `default` one is the trap: the artifact stays ESM (Node ≥22.12 can `require()` an ES module), nothing is built twice, and it reads as free — but its effect is that `require('@pyreon/x')` works, which is the thing the policy forbids. **The policy is about who can consume us, not which files we emit.** Known, accepted cost: we are absent from CJS-only toolchains, including the node half of `moltar/typescript-runtime-type-benchmarks` (ts-node/CJS), so `contrib/moltar/` is bun/deno only. ONE exemption, `@pyreon/storybook`, because Storybook's own preset loader resolves through CJS — a host-tool constraint on a plugin, pinned by `shipped-preset.test.ts`. "It would be convenient for CJS users" is exactly the case this gate rejects.
- **check-doc-claims**: every numeric claim in the docs must match its source — the hook export count, the lint rule + category counts, the detector-code count, the doc-page count, and the rest of the `checks` table in `packages/tools/cli/src/doctor/gates/doc-claims.ts` (which is where the guarded claim SITES live; do not restate a count here, an unguarded copy in CLAUDE.md is exactly what the gate exists to prevent). Write exact numbers at the guarded sites, never "33+".
- **check-manifest-depth**: ratchet on migrated-package MCP `get_api` density (LOCKED packages can't erode below their floor).
- **Diagnose Catalog**: a source change in `packages/core/{runtime-dom,runtime-server,core,compiler,router}/src/` needs an `ERROR_PATTERNS` entry (in `compiler/src/diagnose.ts`) so `pyreon doctor diagnose` teaches the fix (or `skip-diagnose-catalog` label). **`diagnoseError` + `ERROR_PATTERNS` live in the browser-safe `@pyreon/compiler/diagnose` subpath** (pure regex + strings, ZERO `typescript` import — extracted out of `react-intercept.ts`, which pulls the TS compiler API) so the dev throw-time fix printer can load them client-side without dragging `typescript` into the browser bundle; `react-intercept.ts` re-exports `diagnoseError` for back-compat. Locked by `compiler/src/tests/diagnose.test.ts` (bundles the subpath for the browser, asserts no TS-API markers — bisect-verified).
- **Leak Sweep** (`.github/workflows/leak-sweep.yml`, advisory): least-squares heap-slope over the perf-dashboard journeys (dev mode mandatory — counters tree-shake in prod). `bun run perf:leak-sweep`.
- **Docs Freshness Guard** (`.github/workflows/docs-freshness-guard.yml`, main-push self-heal, NOT a PR check): re-runs gen-docs + gen-all on every main push; drift (concurrent-merge staleness — two PRs touching generator inputs merged without seeing each other under non-strict protection) → red run on the offending commit + auto-opened/updated `auto/docs-regen` fix PR (auto-changeset when mcp `api-reference.ts` drifted; automerge armed when `RELEASE_PAT` is configured).
- **Release**: changesets fixed-group (synced version trajectory). check-release-readiness (publishConfig.access + fixed-group coverage), check-published-state (repo vs npm — EVERY publishable package, not sentinels: a PARTIAL RELEASE where some packages lag the cut version is a red, named by package; the 0.51.0 cut left all six `@pyreon/native-*` packages at 0.50.0 for a month under an `OK 4/4 sentinels` verdict). `publish.ts` retries only npm errors with EVIDENCE of being transient (5xx, dropped sockets — never 404/403/conflict, and never `E422 Error verifying sigstore provenance bundle`, which compares the published manifest against the building repo and so reproduces every attempt: that is what cost 0.51.0 its six `@pyreon/native-*` packages, whose manifests carried no `repository` field at that tag — fixed on main the same day by #2727, so the next release ships them). release.yml's `resume-detect`/`resume-publish` republish lagging packages from the release TAG on the next main push (the tag, never main: unreleased work must not ship under a released number), ONCE per version — a release broken by its own tag cannot be rescued by replaying it, so a second attempt is refused with a warning and the daily published-state gate stays the alarm. First-publish of a new package needs a one-time manual OIDC trusted-publisher bootstrap (`scripts/publish.ts` is hardened to non-block on the 404).

## E2E suites

(`bun run test:e2e` + per-suite scripts, real Chromium): playground / ssr-showcase / ui-showcase regression / fundamentals / compat-layers / app-showcase (flow + dnd + charts) / ssg-subpath / ssg-i18n / ssg-i18n-prefix / ssr-node / isr-node / cssvars / zero-hmr / zero-islands / sync-* / **docs** (pyreon.dev itself — registered 2026-08; it had a complete spec file and config that nothing ever invoked, so the public site had zero browser coverage and shipped a dead search overlay). Each suite is its own parallel CI job (flake-isolated). The ui-showcase regression gate covers the 5 packages (runtime-dom/styler/rocketstyle/elements/unistyle) that produced 24% of `fix:` commits — add a spec when a real-app regression surfaces (bisect-verified). Coverage thresholds: `@pyreon/zero` + `@pyreon/lint` ship large `coverageExclude` lists (integration-tier surface gated by e2e/verify-modes instead) — check the exclude list before "fixing low coverage".
