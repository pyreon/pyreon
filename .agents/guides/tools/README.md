# Tool packages — atlas, lathe, loom, testing, CLI

Read before touching `packages/tools/{atlas,lathe,loom,cli}` or `@pyreon/testing`.

## `@pyreon/atlas`

AI-native component workbench — derives a verified, machine-readable component catalog from source (`atlas scan`: controls from props, scenarios from variant axes incl. rocketstyle dimensions, six-check verify verdicts, and a CONTENT SEED merged under every scenario — a text component's name as an editable `children` control, a placeholder `src`+`alt` for `<img>`, a `placeholder` for fields, three placeholder blocks for a layout container — derived from the tag the component renders as (`__rs_attrs` / `__rs_component`) and materialized by ONE `materializeContent` in the verify harness, the SSR-parity check AND the generated workbench render; before it every derived scenario mounted an EMPTY element and the deployed ui-components workbench showed 108 blank previews while reporting 1090/1090 verified). The seed is keyed on the BASE too when a chain renders through a component (`el.config({ component: ModalBase })` → `open: true` + an `open` control the overlay's `onClose` writes back; a select-like base → `<option>` blocks), and a scenario that mounts NO DOM — no element, no text, nothing portaled — FAILS the interaction check with `empty-render` (an `auto-edge` scenario reports it without failing; `browserOnly: [...]` in the config declares a component that returns `null` where `isServer` is true, `parts: { TabPanel: 'Tabs' }` declares one that only renders inside its parent — the canvas then shows the parent's opening scenario for it). Variant scenarios FAN one axis at a time (`Σ|axis|`; `matrix: 'full'` opts back into the `Π|axis|` product that made four layout components 150 scenarios each), every component gets a `Default` unconditionally, edge cases target a CONTENT prop, and an authored `Default` (args stay LIVE — a render-prop child or an `h()` tree written in `atlas.config.ts` reaches the canvas intact) is the base every derived scenario is built on. The canvas OPENS on the `Default` scenario with ALL its args (a `Tree`'s `data`), a link carries only the edits, and the fluid frame spans the stage (it shrink-wrapped to 80px before, collapsing every block-level component to zero width). Gated end to end by `e2e/atlas-ui-components.spec.ts`, which builds the REAL library and measures every page, reports WHICH check failed rather than only how many scenarios did, with every finding STRUCTURED as `{ code, message, fix? }` (catalog v2 — `code` is the stable greppable class an agent branches on, `fix` names the one thing to change and travels WITH the finding so the agent guide/MCP/`--json` all carry the actionable half; MCP REFUSES a stale v1 catalog by version rather than rendering blank findings) (`checks: a11y 18/20 ✗ · interaction 43/43 · …` + `not run:` lines with reasons — `N verified` counts SCENARIOS, so a package where `@pyreon/runtime-server` does not resolve reports 1090/1090 verified having run two of six checks), scopes that to one component for the write→verify→fix loop (`atlas verify <Component> [--json]`: discovery still walks everything, but decorate+verify run only for the match — 1.35s→0.90s on ui-components' 108 comps/1090 scenarios, ~18× less verify work with discovery dominating the residual; NEVER writes the catalog, since a one-component catalog would replace the real one; an unmatched name and a nothing-was-verified run BOTH exit non-zero, because "0 failing" is not a pass), and RATCHETS both commands against the committed catalog (`--check`: exits non-zero on a regression, never rewrites its own baseline, missing baseline = exit 0; a check that STOPPED RUNNING counts as a regression — losing coverage makes the counts IMPROVE, so `2 failing → 0 failing` after a lost wrapper reads as fixed and is not), serves a zero-config workbench (`atlas dev`: real Vite compiler, live controls, canvas addons, axe-core a11y panel, autodocs, Reactivity Lens; re-derives the catalog when a scanned file changes — debounced, serialised, a failed rescan keeps the previous catalog; the sidebar has its own persistent filter (the ⌘K query is the dialog's, cleared on exit), ↑↓ walk the rows the sidebar SHOWS, addon panel bodies build on demand and rebuild per component, a link carries `view`/`pseudo`/`query`/`role`, chrome preferences persist in `localStorage`), runs the browser half of verification (`atlas verify-browser`: reactive coverage measured on the page's OWN devtools-bridge instance — new-node diff, workbench chrome excluded — plus pixelmatch snapshot baselines, merged back into `atlas-catalog.json`), and ships the docs as a STATIC site (`atlas build` → `atlas-dist`, `--out`/`--title`/`--base`; the node-answered panels — Docs source + Reactivity Lens — are BAKED per component into the page, so a serverless deploy keeps real compiler live/static verdicts instead of two silently-dark panels; an uncomputable answer bakes its REASON). Authoring opt-in via `atlas.config.ts` (theme/wrapper/presets/authored `play` scenarios/`title`/`pages` = per-component display title, group, order, summary — presentation ONLY, the real `name` is never overridden since it drives the usage snippet, the source/lens lookup and an agent's import). MONOREPO via `projects: [{name,dir}]` — N packages into one catalog, each filed under its name; a component`s IDENTITY is `componentKey` = `project/Name` (bare `Name` outside a monorepo, so single-package output is byte-identical), which is what keeps two packages` `Button`s apart in the graph, the scenario ids (`core-button--…`), the catalog ids and the baked-RPC payload. An ambiguous bare name REFUSES and names the candidates rather than resolving to the first match. `pages`/`scenarios` accept `Core/Button` or a bare `Button` (which applies to every match). NO singleton sentinel by design — the scan loader loads scanned projects that import atlas

## `@pyreon/lathe`

Spec-to-client generator — OpenAPI 3.x in; `@pyreon/validate` schemas, `@pyreon/http` endpoints, `@pyreon/query` hooks, deterministic mock fixtures and `@pyreon/atlas` scenarios out (`lathe generate`; `lathe check` fails on output stale against the spec, the `gen-docs --check` contract). Spec parsing is FIRST-PARTY, including a YAML reader scoped to the OpenAPI subset that REFUSES anchors, merge keys, explicit tags and tab indentation with a line number rather than mis-reading them. Every reduction the IR cannot represent becomes a `note` with a stable code + JSON-pointer location, so a loss is reported once at the boundary instead of rediscovered per emitter. **`target: 'multiplatform'` is the part with no analogue elsewhere**: PMTC has no module graph — `transform()` takes ONE file and its recognizers see only that file's top level — so a client in `client.ts` and an endpoint in `endpoints/x.ts` are unrelated files to it and the call stays web. Generated code has no opinion about file layout, so the native target emits one self-contained module per tag (client + schemas + endpoints + calls sharing a top level) and then runs the REAL compiler over its own output, asserting the POSITIVE marker (`PyreonQuery<`, `PyreonZodSchema_`) plus the absence of leaked web-only symbols — zero warnings is NOT evidence, since a standalone hook wrapping `useQuery` produces none and emits Swift that cannot find the symbol. A `does NOT compile` warning is treated as broken, not advisory; an absent compiler SKIPS loudly. Per-operation reach is reported in SPEC terms (a path parameter is supplied at runtime and PMTC bakes URLs at compile time, so that operation is named `web-only`). Deterministic by construction — sorted models/operations/imports, no randomness in fixtures — so an unchanged spec regenerates byte-identically. **Output is a LAYERED graph, not one barrel** (`index.ts` production · `dev.ts` fixtures/factories (node-safe) · `endpoints/index.ts` + `queries/index.ts` per layer · per-tag files), plus an emitted `package.json` whose `sideEffects` makes the whole graph tree-shakeable regardless of the consuming app's own config — measured with Vite on a 120-operation spec, one hook went 30.7 kB → 5.7 kB (2,420 → 642 gz) and 120 mock fixtures → 0. The dev isolation is STRUCTURAL, not marker-dependent: `index.ts` never NAMES `./faker`/`./mocks`/`./components`, so no bundler has an edge to follow (24-case matrix asserts it with AND without the marker; the no-marker half is the load-bearing one, since with the marker a regression shakes out invisibly). `/* @__PURE__ */` per declaration was measured and REJECTED as the fix (2,041 → 2,000 B, 2% — the arguments are themselves calls). Nine plugins: `types`/`schemas`/`client`/`queries`/`mocks`/`faker`/`components`/`atlas`/`docs`. `faker` emits `createX(overrides?)` per model where CONSTRAINTS outrank realism only as far as a realistic generator can be made to satisfy them — a real `minLength` falls back to `alpha`, a `maxLength` alone keeps the readable generator plus a slice, a `format` is never clamped; `docs` renders Markdown+frontmatter documenting the GENERATED client (hook name, import site, and the reach column no rendering of the spec can produce)

## `@pyreon/loom`

Monorepo dependency observatory — `loom scan` reads the workspace like an install tool (npm/bun/yarn/pnpm globs incl. `packages/*/*`) and emits the fabric as DATA: internal graph (longest-path depths V-1-bounded, RUNTIME cycles — dev edges deliberately excluded, blast radius), external version-usage map, and 8 detector codes with honest severities (version-drift with peer-contract + strict-superset-containment recognition / internal-range / cycle / phantom-dep + phantom-type-dep / prod-import-of-dev-dep / peer-mismatch / unused-dep-as-info). TYPE-AWARE: `import type` / `export type` (multi-line included) and everything in a `.d.ts` are tracked apart from runtime imports, and tsconfig `paths` aliases (`~/*`, `@app/*`) never scan as packages — both were false-positive classes found by scanning a real FOREIGN monorepo. Configured from the root `package.json`'s `loom` key OR a `loom` section in `pyreon.config.*` (same shape, manifest wins per key): `devPaths` (globs that are NOT shipping source — on this repo one entry takes 73 gating warnings to 18), `ignore` (reason mandatory), `strict`, per-code `severity`. Served to agents by MCP `get_dependency_fabric`; red exit gates CI, `loom-report.json` is the machine surface. `loom dev` serves the five-view observatory (layered graph / adjacency matrix / cycle cards / impact ranking / manifest table + detail panel, ⌘K, ↑↓, dark/light) on the PUBLIC Pyreon UI stack; vite + vite-plugin OPTIONAL peers. Lexical import scan strips comments + template literals (recipe catalogs carry import lines as strings). Reads DECLARED truth only — no lockfile/registry (documented future layers). NO singleton sentinel (tool precedent)

## `@pyreon/testing`

PUBLIC test kit at Testing-Library parity — `render`/`screen`/`cleanup` + the full query families (`getByText`/`getByRole`/`getByTestId`/…), `fireEvent` (dispatches real bubbling events through Pyreon's delegation root — delegated AND direct-listener/non-bubbling paths verified in real Chromium), `waitFor`/`waitForElementToBeRemoved`, `renderHook` (Pyreon fine-grained semantics — hook runs ONCE; `rerender` updates the reactive props signal, NOT a re-invoke), jest-dom matchers via `@pyreon/testing/matchers` + the `/vitest` setup file (auto-cleanup + matchers). PLUS Pyreon-native reactive matchers (`expectSignal`/`expectEffect` — fire-count/re-run assertions no DOM-only lib can express) and GC/leak matchers (`expectGarbageCollected`/`expectNoReactiveLeak`). PLUS library-helper SUBPATHS gated on optional peers (NOT re-exported from the main entry): `/form` (`renderForm` headless useForm harness + `fillForm`/`submitForm` by accessible LABEL through real events + `expectForm`), `/ui` (`renderWithTheme` + reactive `setMode`; `expectComputedStyle` — computed-serialization normalization, real-browser territory), `/router` (`renderWithRouter` — ASYNC, initial route SETTLED via `router.preload` so `useLoaderData` is populated on first render; `navigate()` resolves post-commit; `expectRouter.toBeAt` matches pattern OR concrete path), `/store` (`installStoreReset`/`withFreshStore` — compose store's dispose-on-reset), `/i18n` (`renderWithI18n` + `setLocale`), `/toast` (`expectToast`/`findToast`/`clearToasts` — STORE-level, string messages only), `/query` (`renderWithQueryClient`/`createTestQueryClient` — retry off + `gcTime: Infinity`); every harness takes `wrapper` for provider composition (no mega renderApp). Fluent-assertion convention (`expectForm(form).toBeValid()`), never `expect.extend`. Adapter convention (wraps `@testing-library/dom`+`jest-dom`, like `@pyreon/query` wraps TanStack). Browser package. Distinct from the private `@pyreon/test-utils` (framework-internal).

## `pyreon` CLI and `pyreon doctor`

- `pyreon check [paths]` — fast, file-scoped COMPILER-detector scan (`detectPyreonPatterns` + `detectReactPatterns`) with inline fixes; no paths → git-changed `.ts/.tsx`; `--fix` applies `migratePyreonCode`+`migrateReactCode`; `--json`; exits non-zero on findings — the terminal-native twin of MCP `validate`, distinct from `doctor`'s whole-project gates and `lint`'s rule set.
- `pyreon add <pkg…>` — install one or more `@pyreon/*` packages with the project's PM auto-detected from the lockfile (bun/pnpm/yarn/npm, walking up from cwd), then print a tailored, verified setup recipe per package: root provider to add + a usage snippet + docs link; bare names normalized `query`→`@pyreon/query`; recipes are CLI-LOCAL in `add-recipes.ts` — NOT generated from manifests, since manifests aren't shipped in published packages; `--dry-run`/`--json`; an `@pyreon/*` pkg without a curated recipe still installs with a generic docs pointer.
- `pyreon new [name] [--native]` — scaffold a new project; a thin dependency-free delegator that `npx`-runs `@pyreon/create-zero@latest`, or `@pyreon/create-multiplatform@latest` with `--native`; all other args pass through to the scaffolder's interactive flow; `--dry-run` prints the npx command; `@latest` so a new project always starts on the freshest templates regardless of the installed cli version.
- `pyreon mcp [args]` — launch the Pyreon MCP server; a thin dependency-free delegator that `npx`-runs `@pyreon/mcp` (the stdio server serving API reference / patterns / `validate` / `diagnose` to AI assistants); deliberately WITHOUT `@latest` so it prefers the PROJECT-LOCAL `@pyreon/mcp` — the served API reference then matches your installed Pyreon version — fetching on demand only when absent; extra args + `--dry-run` pass through; inherits stdio so the spawning AI client talks to it directly.
- `pyreon plain [paths] [--write] [--json]` — Plain-Mode readiness report (per-file convertibility, every declined shape NAMED, declined-shape histogram); `--write` applies the per-binding classic→plain codemod in place. No paths → whole tree under cwd (a readiness question is project-level, unlike `check`'s git-changed default).
- `pyreon lint` (forwards every `pyreon-lint` flag via `runCli`), `pyreon info` (env + `@pyreon/*` version-skew), `pyreon upgrade` (align versions).
- `pyreon doctor` — 15 gates (react-patterns/pyreon-patterns/lint/distribution/doc-claims/islands-audit/ssg-audit/content-audit/native-audit/audit-tests/check-dedup/audit-leak-classes/dependency-fabric + slow audit-types/bundle-budgets); `dependency-fabric` runs the project's OWN `@pyreon/loom` (resolved, never fetched) and SKIPS when absent — a skipped category is excluded from the mean, never scored 100; 0-100 score; `--full`/`--fix`/`--json`/`--gha`/`--ci`/`--only`/`--skip`/`--roots`; advisory `best-practices` category excluded from grade + `--ci`. **File-scanning gates resolve scope from the workspace's OWN `workspaces`/pnpm globs** (`doctor/utils/workspace-roots.ts` — one resolver, cwd-independent, multi-root layouts covered; `pyreon.doctor.excludeRoots` in root package.json excludes examples/docs; the Pyreon repo's own config keeps the audited set byte-identical). **An empty scan is a SKIP + warning, never a clean pass** (`meta.emptyScan`; category not measured), and a run where NOTHING was measured renders `—` instead of the degenerate 100/A + fails `--ci` (`report.measured`) — closes the upstream multi-root false-green report.
