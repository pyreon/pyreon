The Kotlin emission of every `@pyreon/charts` host moves out of the core's `emit-kotlin.ts` into the built-in `@pyreon/charts` plugin (`plugins/charts/kotlin*.ts`, ~1,800 lines), so a chart host is claimed entirely by the element registry on both targets and neither emitter keeps a chart branch. Emitted Kotlin is byte-identical (golden corpus plus a transform-capture comparison over every chart test). `stringAttr`, `layoutModifiers`, `action`, `constExpr` and `colorScope<T>()` move from `SwiftEmitContext` up to the shared `EmitContext` (the Kotlin emitter now supplies them; the backend interface gains them), so `emit.kotlin` can read them; `SwiftEmitContext` keeps only `handlerName`, `markColorSchemeUsed()` and `hostState`, which have no Compose analogue. Two Kotlin behaviours change, both correctness fixes mirroring the Swift slice: a chart tag is claimed only when imported from `@pyreon/charts` under its own name and not shadowed (a user's own `Legend` or `Cell` component is no longer mistaken for a chart mark on Android either), and the "spread is not lowered" / "JSX-valued attribute no emitter reads" warnings run before a registry-claimed `emit.kotlin`. Additive for plugin authors (API version stays 1).
