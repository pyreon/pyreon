The plugin interface grows by exactly what the chart-handle lowering was measured to use, each proven by moving a real piece of it out of the core. `CompilerPlugin.memberCalls` lets a plugin claim a call EXPRESSION (`<receiver>.<method>(...)`) on a binding one of its own declarations created (receiver-keyed, so two plugins may share a method name; `undefined` declines). `EmitContext` gains `expr(e)` / `exprAs(type, e)` (emit a sub-expression, optionally steering a literal's type), `decls(plugin, type)` (the component's declarations of that kind), `state(key, init)` (memory that lives for one component and is reset between components, files and compiles), and `deferred(key, fallback?)` / `resolveDeferred(key, value)` (a value known only after the component body has emitted; an unresolved token with no fallback is an error naming the key, replacing the private `__PYREON_HANDLE_SERIES_<name>__` placeholder). `CompilerPlugin.unlowered` lets a plugin own its package's "has NO native lowering" advice and `supported` list, merged into the instance registries (`registries.unlowered`). `handle.dispatch({...})` and the `@pyreon/charts` advice now live in the built-in charts plugin; the emitters' handle-name sets, series map and placeholder regex are gone. Emitted Swift and Kotlin are byte-identical. A handle keyword-escaped by `ident` now also gets its series count (the old placeholder keyed on the raw name). This is additive; the plugin API version stays 1.
