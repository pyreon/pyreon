The `@pyreon/validate` / `@pyreon/validation` native lowering moves out of `@pyreon/native-compiler` into the packages themselves (`@pyreon/validate/native-plugin`, `@pyreon/validation/native-plugin`). The compiler no longer names either package in its source (boundary baseline: `@pyreon/validate` 5 -> 0, `@pyreon/validation` 8 -> 0). Ownership follows activation: `@pyreon/validation` owns the `zodSchema` / `valibotSchema` / `arktypeSchema` recognizers and the shared schema model (walker, Swift / Kotlin emitters, URL rules, form validators, response-type evidence); `@pyreon/validate` owns `s.object`, `withField` and `safeParse`, and registers the shared model under its own plugin name, so neither needs `requires` (discovery only sees an app's DECLARED dependencies). Emitted Swift and Kotlin are byte-identical for every golden entry (954; 17 more validate fixtures were recorded from the parent compiler first, covering the schema paths the corpus never reached; none updated).

`@pyreon/native-compiler` gains four library-agnostic module-level seams, exported through `@pyreon/native-compiler/plugin-api`: `topLevel` + `items` (the open `ExtModuleItem`: a plugin's own file-scope declaration, emitted in a plugin-declared slot, with a `legacyList` hash lane, value/type `bindings` and `fieldValidators` a `useForm({ schema })` reads), `methodCalls` + `exprs` (the open `ext-expr` node, rendered, typed, renamed and hashed by its owner; the key `'*'` sees every method call), `refineStructs` (decode types settled from items) and `finishModule`. `ParseResult.fieldMetas` / `zodSchemas` and the `schema-validate` expression kind are gone (`moduleItems` / `ext-expr`); the plugin-api also exports the pure spelling helpers the emitters share with plugins (`KOTLIN_INT`, `swiftCodingKeysLines`, `localBase`, `kotlinMember`).

Behaviour changes: a bare `transform()` / `createCompiler()` with no discovery no longer lowers schemas (load the plugins yourself; `pyreon-native` discovers them and `--no-plugins` turns them off); the Tier-2 declines (`withField`, `zodField`, …) now require the call to be imported from the package; the `useForm({ schema })` "no declaration" warning names its libraries from the loaded plugins; a rename for a value/type clash can no longer land on a name a nested schema already takes. `@pyreon/lathe`'s native verifier loads the project's own `@pyreon/validate` / `@pyreon/validation` plugins before compiling generated output.
