'@pyreon/auth': minor

Sign-out revokes tokens, Android's redirect activity accepts only the answer to its own request, one callback-parsing rule on every target, and a way off legacy TOTP secrets.

- **Token revocation (RFC 7009).** `createAuth().signOut()` (and `useOidc().signOut()`) clears the local session at once and, when the provider advertises a `revocation_endpoint`, revokes the refresh and access tokens there. It now returns `Promise<{ revoked, error }>` instead of `void`; a refused or unreachable revocation still signs out locally and is reported in `error`. `revokeTokens: false` skips it. With `endProviderSession` the provider-logout redirect waits for the revocation (at most 5 s), and is skipped when a new sign-in started meanwhile. A code exchange or refresh still in flight at sign-out has its token response revoked when it lands (and so does any token response that is discarded, e.g. on a bad ID token) instead of being dropped while still valid; `revoked` covers the tokens held at the call. New export `revokeToken(meta, client, token, { tokenTypeHint?, fetch?, signal? })`; `OidcMetadata.revocation_endpoint` is read from discovery and must be https.
- **Native sign-out** (iOS and Android) revokes the same way when the provider advertises it, and signs out every other live `PyreonOidcAuth` over the same stored session in the process (they share the record the sign-out removes), revoking every token any of them or the stored record holds — so a sibling's rotated refresh token is revoked too. Token responses that land after a sign-out are revoked as on the web. New `signOutNow()` awaits / blocks on the provider work. The compiler reports `signOut({ revokeTokens })` in shared code, since native always revokes.
- **Android redirect activity.** The exported `PyreonAuthRedirectActivity` now forwards a redirect only when it arrives at the pending request's redirect target with that request's `state` (`PyreonRedirect.answers`), so another app can no longer cancel or feed a sign-in by starting it. A provider error sent without `state` is now dropped, and the user's return to the app reports `cancelled`. The README documents verified App Links as the way to stop another app from claiming a custom scheme.
- **Callback parameters** are read by one rule on the web, iOS and Android, held to shared vectors (`native/tests/callback-vectors.json`): the first value of a repeated parameter wins (Android read the last), `+` is a space (iOS kept it), an opaque callback such as `com.example.app:oauth?code=…` has a query on Android (it read none), and a bad `%` escape stays literal and invalid UTF-8 becomes U+FFFD on every target (natively one bad escape used to empty the whole query).
- **TOTP migration.** `verifyTotpWithMigration(secret, code)` verifies a legacy 80-bit enrolment and returns a fresh 160-bit `reEnrol` secret to move the user to (null for a secret that is already 128 bits or more).

Upgrade: code that relied on `signOut()` returning `undefined` gets a promise; nothing else changes for existing callers.
