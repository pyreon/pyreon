The `@pyreon/flow` native lowering moves out of `@pyreon/native-compiler` into `@pyreon/flow` itself (`@pyreon/flow/native-plugin`). The compiler no longer names `@pyreon/flow` anywhere in its source (the boundary count goes 13 → 0), and `createFlow` / `useFlow`, `<Flow>` and its satellites, the edge-path / marker / layout helpers and `<FlowWebView>` are lowered by a plugin the package ships. Emitted Swift and Kotlin are byte-identical for every golden entry (536, 142 of them flow fixtures recorded from the parent compiler before the code moved; none updated).

`@pyreon/native-compiler` gains the hooks a code-shaped library plugin needs beyond declarations and elements, each library-agnostic and exported through `@pyreon/native-compiler/plugin-api`: `CompilerPlugin.receivers` (calls, member reads and assignments ROOTED at a plugin declaration's binding — `flow.nodes.set(x)`, `flow.config.zoom = 2`), `functions` (plain `name(args)` helpers, claimed like hooks with alias resolution), `identifiers` (library constants), `memberReads` (reads recognised by shape, `MarkerType.Arrow`), `intrinsics` (lowercase DOM tags a plugin gives meaning to inside its own renderers), `prepareEmit` + `EmitContext.fileState` (a per-file pass that may add components), `propsTypes` (a library's imported props types, with inline-type-argument struct lifting), `intrinsicAdvice`, `unlowered[module].dropped`, `ElementLowering.aliasable`, and `DeclEmitter.lifecycle` (stable host + dispose lines). The parser facade (`ParseContext`) exposes the call's arguments and the AST readers a recognizer needs, and `EmitContext` gains `component()`, `structs`, `typeText`, `inferType`, `child`, `warnOnce`, `webView`, `layoutModifiersFor` and `isFunctionName`; Kotlin lowerings receive a `KotlinEmitContext` (`intArg`). The `flow-state` declaration kind is gone from `DeclIR` (it is an `ext` declaration owned by the plugin).

`@pyreon/flow` ships the plugin (manifest `pyreon.native.plugin` + `modules`, optional peer on `@pyreon/native-compiler`), so `pyreon-native build|check` loads it when a source file imports the package. Behaviour changes: a bare `transform()` / `createCompiler()` with no discovery no longer lowers `@pyreon/flow` (load `@pyreon/flow/native-plugin` yourself; `--no-plugins` turns it off); the flow helper functions are now claimed like hooks, so a same-named user function or foreign import is left alone instead of being lowered; `<Handle>`, `<NodeResizer>`, `<NodeToolbar>` and `<EdgeLabelRenderer>` are claimed through the import guard like every other element (a same-named user component is no longer mistaken for them); and the flow-specific advice in the "DOM/SVG element has no native lowering" warning appears only when the flow plugin is loaded. The generated `<FlowWebView>` host moved with it (`bun scripts/gen-flow-webview-host.ts`).
