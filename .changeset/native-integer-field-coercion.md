'@pyreon/native-compiler': patch
---

A whole-valued Double stored into an integer struct field now converts instead of failing the native build. `todos.update((t) => [...t, { id: Date.now(), title }])` with `id: number` compiled with no warning and failed both Swift ("cannot convert value of type 'TimeInterval' (aka 'Double') to expected argument type 'Int'") and Kotlin ("actual type is 'Double', but 'Long' was expected"). `Date.now()` now lowers to integer milliseconds in that position (`Int(Date().timeIntervalSince1970 * 1000)` / `System.currentTimeMillis()`), and `Math.floor` / `ceil` / `round` / `trunc` (and `+ - * %` over them and integers) convert exactly, at both the constructor and the `{ ...t, id: … }` spread-override sites. Any other Double value stored into an integer field (for example `Math.random()` or a division) is now named with a warning instead of compiling silently into a broken build: declare the field `Double`, or round the value. An annotated local whose literal gives a field a fractional value (`const row: Row = { value: 1.5 }`) now makes that field `Double`, as a signal seed already did. Before this change, the field stayed an integer next to a `1.5` argument and failed both builds silently.
