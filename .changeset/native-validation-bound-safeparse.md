`@pyreon/validation`'s native lowering now covers the schema AFTER it is declared, and names what it cannot lower instead of dropping it. Several schemas in one statement (`const a = zodSchema(…), b = zodSchema(…)`) each become their own native struct (the statement was re-emitted verbatim, which neither swiftc nor kotlinc accepts, with no warning). `.safeParse(x)` on a declared schema binding or on an inline `zodSchema(z.object({ … })).safeParse(x)` lowers to the same `{ success, data }` result the web returns and `@pyreon/validate`'s `s` DSL already produced (it was a static method called through an instance with a struct where a dictionary belongs, compiling on neither target). `.parse()` throws and PMTC has no error model, so it is a named warning that points at `.safeParse()`, as is `.safeParse()` on a `discriminatedUnion` and a schema declared inside a component body. Modifiers the native struct does not enforce (`.refine`, `.transform`, `.default`, `.nonempty`, `.trim`, an object-level chain, a non-literal `.min(n)`, a constraint on a boolean/array field) were dropped silently, so a device accepted input the web rejects; each is now reported by name. `.min(-1)` reads its negative bound. The shared `safeParse` expression moved into `@pyreon/validation/native-plugin` so both plugins use one copy.
