Islands-only pages. `export const hydrate = 'islands'` on a route or `_layout` (cascading like `renderMode`; `'app'` opts a page back in) ships the page as static HTML plus its `island()`s: the server still runs the loader and renders its output, but leaves out the `__PYREON_LOADER_DATA__` script and the route's modulepreloads and marks the page with `<meta name="pyreon-hydrate" content="islands">`. In the browser, `startClient` and the new `startClientLazy` (`@pyreon/zero/client-lazy`, which loads the routes and the app with dynamic imports) hydrate only the islands, from the `islands` registry you pass (`import * as islands from 'virtual:pyreon/islands-registry'`), optionally wrapped in an `islandRoot` component that provides context; no router starts. A client-side navigation to an islands-only route is a full page load. `zero({ routeRules: { '/docs/**': { hydrate: 'islands' } } })` declares it centrally, with the precedence `renderMode` has (a page's or `_layout`'s own export wins). A computed or unknown `hydrate` (export or rule), or an islands-only page that renders `'spa'`, is a `[Pyreon]` error when the routes module loads. A build whose routes and rules never declare `hydrate` compiles the support out of `startClient`. Every page preloads what its client starts from: app pages the lazy entry's app chunks, islands-only pages with an island the islands runtime, under SSG, SSR (string and streaming) and ISR alike. In dev, an edit to a module the server rendered an islands-only page with reloads that page. When every page is islands-only, the production client build carries no app code (the router included), and the islands runtime is one chunk.

`@pyreon/server`: `renderPage` and both `createHandler` modes honour `meta: { hydrate: 'islands' }` (new exports `ISLANDS_ONLY_MARKER`, `isIslandsOnlyMeta`, type `PageHydration`; `RenderPageResult` gains `hydrate`), and `hydrateIslands` / `hydrateIslandsAuto` take `{ root }`, a component loaded with the first island that wraps every island in its providers. `createHandler({ clientPreload: { app, islands } })` emits modulepreloads per page kind (new type `ClientStartPreload`). `startClient({ islandsOnly: islandsOnlyPages(start) })` (new exports `islandsOnlyPages`, `ISLANDS_ONLY_SELECTOR`, type `IslandsOnlyPages`) runs `start` instead of the app on a marked page and makes a navigation to an islands-only route a full page load; an app that does not use it pays 47 B gzip.

Upgrade: none
