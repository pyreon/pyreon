---
'@pyreon/format': minor
---

Number formatters take decimal strings (`'12345678901234567.89'`) and format them exactly at any size. Ranges are exact too, on every engine: V8's own `formatRange` rounds string ends to doubles, so Pyreon takes the range's shape from `Intl` and the digits from each exact end. Ends that are numbers, bigints and decimal strings are ordered exactly. `formatCurrency(m, options?)` and `currencyFormatter(code)` take a Money (`{ amount, currency }`) and show it with its own digits, the same on every engine. A custom code such as `USDT` (2 to 12 upper-case letters or digits) is placed where the locale puts a currency code. An amount with more fraction digits than the engine supports gives the fallback with a dev warning instead of throwing. `NumberInput` now includes `string`; any string that is not a plain decimal still gives the fallback with a dev warning. The docs now explain that `formatDateRange` uses the locale's CLDR interval data (Czech numeric ranges repeat the year), and that a conversion with `convertTo` is binary-float arithmetic and therefore not exact. A test checks that `formatDateRange` matches `Intl.DateTimeFormat#formatRange` across locales.
