`useWakeLock`, `useDeviceInfo`, `useDeviceMotion`, `useSpeech`, `useAudioRecorder`, `useBluetooth` and `useCamera` compiled to engines named by the emit (Kotlin `AndroidScreenKeeper`, `AndroidDeviceProbe`, `AndroidMotionSource`, `AndroidSpeechSynth`, `AndroidRecordingEngine`, `AndroidBluetoothScanner`; Swift `UIKitIdleTimer`, `UIKitDeviceProbe`, `UIKitCameraPresenter`, `CoreMotionSource`, `AVSpeechSynth`, `AVFoundationRecordingEngine`, `CoreBluetoothScanner`) that existed only in the validation stubs — an app using any of the hooks could not build against the real SDK while every stub gate stayed green. The real engines now ship in `@pyreon/hooks` native (`PyreonDeviceProbesAndroid.kt`, `PyreonDeviceProbesUIKit.swift`) with the web arm's semantics: motion is m/s² including gravity with the W3C sign and rotation in deg/s, a recording returns a `file://` URI, a wake lock is the window / idle-timer flag, BLE discovery is first-seen and permission denial lands in `error`. Microphone / BLE-scan permission is requested at call time and the call reports the ordinary "denied" outcome; the next call succeeds. On Android the hook state classes are now `RememberObserver`s, so a recording, scan, sensor or wake lock is released when its screen leaves composition (the iOS twin does this in `deinit`). The Android display probes no longer depend on `RememberObserver` — the emit remembers the wrapper, not the probe, so Compose never notified it — and instead attach their layout watch lazily on first read. The `emitted-runtime-types-exist` ratchet list is now empty and its owned-name pattern covers the Apple-flavoured engine names.
