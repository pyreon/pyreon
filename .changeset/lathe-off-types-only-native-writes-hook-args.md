---
'@pyreon/lathe': minor
---

`responseValidation: 'off'` at generate time now declares those endpoints types only (#4815). The response, error and stream-event bodies are typed from the model interfaces (`api.endpoint<'GET /items', (raw: unknown) => Items, …>`), every model is an `import type`, and no schema is referenced. So neither the schema modules nor `@pyreon/validate` (or zod) ship with those endpoints: one `GET` over a nested response went from 21.9 KB to 6.8 KB gzipped. Error bodies keep `err.matched`: each declared status maps to the identity `unchecked` exported from the generated `client.ts`. `operations.<id>.responseValidation: 'off'` does the same for one operation, and a per-operation `'strict'` or `'warn'` on an `'off'` project keeps its schemas. For `'strict'` and `'warn'`, nothing changes, including `configureApi({ validate })` switching modes at runtime.

Writes reach native (#4835). With `target: 'multiplatform'`, a `POST` / `PUT` / `PATCH` / `DELETE` with a JSON body (or none) and a typed JSON response (or no content) gets an `<Op>Mutation` component in its tag's `.native.tsx` module. The component is `useMutation<T, E, Vars>(op.mutation())`, which `@pyreon/query`'s native plugin lowers to the `PyreonMutation` runtime. `children(mutate, data, isPending, error)` receives the trigger (`data` only when the response is typed). Path parameters and the body are props, read when `mutate` is called. The reach report counts these writes as reaching native. A write that cannot be lowered names the reason: a non-JSON body or response, a required query, header or cookie parameter, a path parameter named `json` or `children`, or `hook: false`. The stale "PMTC does not yet recognise mutations" reason is gone, and the native verifier expects `PyreonMutation<` wherever a module uses `useMutation`.

Every generated read hook takes the same `args` accessor first (#4841). It is optional for an operation without parameters, so `useListThings(() => ({ meta, headers, timeout }))` sends them with the request. Returning `undefined` holds the request, as on a hook with parameters. Query options move to the second argument, which now also takes `key: (base) => [...base, discriminator]` to extend the cache key, including on infinite hooks. Start from `base`, so invalidating the endpoint still matches.

Breaking:

- A hook for an operation without parameters took its query options first: `useListThings(() => ({ staleTime }))`. Pass them second: `useListThings(undefined, () => ({ staleTime }))`. The old call is now a type error, because query options are not request options.
- With `responseValidation: 'off'` at generate time, `configureApi({ validate: 'strict' })` has no schema to check those endpoints against. Generate with `'strict'` or `'warn'` to keep the runtime switch.
