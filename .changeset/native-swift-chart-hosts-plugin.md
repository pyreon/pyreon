The Swift emission of every `@pyreon/charts` host moves out of the core's `emit-swift.ts` into the built-in `@pyreon/charts` plugin (`plugins/charts/swift*.ts`, ~2,000 lines), declared as one element lowering whose `emit.swift` entry the registry reaches. Emitted Swift is byte-identical (golden corpus plus a transform-capture comparison over every chart test); Kotlin has no `emit.kotlin` on the lowering yet and falls through to the core's chart branch. `EmitContext.expr` / `exprAs` take an optional indentation, and `emit.swift` now receives a `SwiftEmitContext` that adds the members only the Swift emitter has state for: `stringAttr`, `layoutModifiers`, `action`, `handlerName`, `constExpr`, a read-only `colorScope<T>()`, `markColorSchemeUsed()`, and a `hostState` slot (`declare` / `lines` / `replaceFrom` / `freshSuffix`) — each added only because the moved code uses it. Two behaviours change, both correctness fixes: a chart tag is claimed only when imported from `@pyreon/charts` under its own name and not shadowed (a user's own `Legend` or `Cell` component is no longer mistaken for a chart mark), and the "spread is not lowered" / "JSX-valued attribute no emitter reads" warnings now also run before a registry-claimed `emit` lowering, so `<PieChart {...props}>` and a spread on any plugin element warn instead of silently dropping props. Additive for plugin authors (API version stays 1).
