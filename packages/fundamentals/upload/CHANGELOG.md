# @pyreon/upload

## 0.54.0

### Minor Changes

- [#4738](https://github.com/pyreon/pyreon/pull/4738) [`e8fedbe`](https://github.com/pyreon/pyreon/commit/e8fedbe3ad940127ec9337b73ec9be1d2a3c9a04) Thanks [@vitbokisch](https://github.com/vitbokisch)! - New package `@pyreon/upload` (Experimental), first release: file selection, validation, preview and upload with progress as signals.

  - **Core (`@pyreon/upload/core`, no dependencies):** `validateFile` / `validateFiles` (size as bytes or `"10 MB"`, `accept` like the HTML attribute, image dimensions, `sniffType` magic numbers, your own rule; rejections have a `code`, a message and `params` for i18n), chunk planning (`planChunks`, never reads the file), progress math, and an error taxonomy that says what is retryable (`errorFromStatus`, `parseRetryAfter`).
  - **Queue (`createUploader` / `useUploader`):** concurrency limit and fair order, pause, resume, cancel, retry with jittered back-off for failures a retry can fix (never a 4xx; `Retry-After` honoured), offline pause, previews as object URLs that are revoked, progress that never goes backwards and is written once per animation frame, and a `dispose` that leaves no request, timer, listener or object URL.
  - **`@pyreon/upload/transport-xhr`:** `xhrTransport` sends with XMLHttpRequest (real upload progress), optionally through an `@pyreon/http` client so its base URL, headers and middleware apply.
  - **State for the DOM:** `useFilePicker` (same file twice works, cancel detected) and `useFileDrop` (counted enter and leave, folders, paste, judged while dragging).
  - **Resumable transports (own entries, none imports another):** `chunkedTransport` (a small documented server contract with a reference handler: init, parts with optional SHA-256, complete, delete), `s3Transport` (presigned single and multipart, no SDK; the app supplies `presign`, `create`, `signPart`, `complete`, `abort`, `list`) and `tusTransport` (tus 1.0 with creation and termination). They save resume state after every part; `createResumeStore` persists it (for example in `localStorage`) so an upload continues after a page reload, and the finished parts are not sent again.
  - **Headless components and adapters:** `@pyreon/upload/components` has `<FileDrop>` (a labelled `role="button"` zone that opens the dialog on Enter and Space, with a live region for refusals and their reasons, focus returned after intake, drag state that does not flicker over children, case-insensitive `accept`) and `<FilePicker>`; `@pyreon/upload/form` makes files a normal `@pyreon/form` field (`bindFileField`, `fileValidator`; resetting the form clears the queue); `@pyreon/upload/query` is `uploadMutation` for `useMutation`.
