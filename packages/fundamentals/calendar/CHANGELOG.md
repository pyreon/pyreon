# @pyreon/calendar

## 0.55.0

### Minor Changes

- [#4811](https://github.com/pyreon/pyreon/pull/4811) [`3ac3403`](https://github.com/pyreon/pyreon/commit/3ac34038befc9fc9634f5264c9e5cbc58bb829b1) Thanks [@vitbokisch](https://github.com/vitbokisch)! - `businessHours` is now read through `@pyreon/schedule`'s `openingWindows`, so the time grid's shading and `constrainTo: 'businessHours'` agree with schedule's `isOpen` minute for minute. Breaking: a `BusinessCalendar` without `weekend` now closes Saturday and Sunday (schedule's default; it was no weekend), a holiday no longer cuts off the previous night's overnight window, and `specialHours` is honoured. A bare `WorkingHours` still opens every weekday it lists. Fixed on the way: a change ending exactly at closing time was refused by `constrainTo: 'businessHours'` (a rounding error in the minutes).

  Also breaking: `businessHours` used to be parsed leniently; it is now validated by `@pyreon/schedule`. A malformed value (a weekday key outside 1 to 7, a window list that is not an array, a time that is not a `PlainTime`, an empty window where `from` equals `to`, a holiday that is not a `PlainDate`, a holidays predicate that throws or does not return a boolean, a malformed `specialHours` entry) reports schedule's `[Pyreon]` error when the time grid is computed, and the grid does not render. Hours that open nothing are not an error and shade the whole grid closed: `{}`, `{ hours: {} }`, and a `specialHours` map with no entry or only empty lists (schedule's business-time functions throw "no hours" for the last; a view shows closed instead). A `BusinessCalendar` with neither `hours` nor `specialHours` shades nothing, as before.

## 0.54.0

### Minor Changes

- [#4738](https://github.com/pyreon/pyreon/pull/4738) [`e8fedbe`](https://github.com/pyreon/pyreon/commit/e8fedbe3ad940127ec9337b73ec9be1d2a3c9a04) Thanks [@vitbokisch](https://github.com/vitbokisch)! - New package `@pyreon/calendar` (Experimental): an event calendar. No drag, resize, agenda, year or timeline yet.

  - **Core (`@pyreon/calendar/core`, no DOM):** the event model (a date is an all-day event, a date-time is a wall clock in the event's own `timeZone` or floating, a number is an instant; the end is exclusive; `allDay(date, days?)`), `expandOccurrences` (recurrence and overrides through `@pyreon/schedule`), view windows with navigation and titles, month lanes (`layoutRow`, `layoutMonth`) and time-grid column packing (`packColumns`, `layoutDay`, `layoutTimeGrid`, pinned columns, per-day signatures) as pure functions with stable keys, a wall-clock time grid with defined behaviour on the 23 and 25 hour days, and the now line (`nowOffset`).
  - **`createCalendar`:** the view and the anchor date (values, or signals you own), the window and the title in the active locale and zone (`@pyreon/ambient`, `@pyreon/format`), the `month()` and `timeGrid()` view models with layouts memoised per week and per day (changing one event recomputes only the days it touches), the focused cell, a selection, `onRangeChange`, `onSelect`, `onEventClick`, and the grid keyboard (`gridMove` and `slotMove` are pure and exported for a date picker to share).
  - **Components (`@pyreon/calendar/components`, `@pyreon/calendar/styles.css`):** `<Calendar>`, `<MonthView>`, `<WeekView>`, `<DayView>`, `<CalendarToolbar>`: WAI-ARIA grids with one tab stop, events as labelled buttons ("Design review, Wednesday 18 November, 14:00 to 15:00"), today and selection marked, "+N more", an all-day row, opening-hours shading, a now line from the ambient clock, a live region for navigation, right to left, render slots and CSS hooks. Renders on the server and hydrates without a mismatch.
