# @pyreon/format

## 0.55.0

### Minor Changes

- [#4813](https://github.com/pyreon/pyreon/pull/4813) [`1a039d7`](https://github.com/pyreon/pyreon/commit/1a039d7348c4dd441ecd5f25594328bf75e21fdb) Thanks [@vitbokisch](https://github.com/vitbokisch)! - Number formatters take decimal strings (`'12345678901234567.89'`) and format them exactly, at any precision, within the double range. A decimal string beyond about 1.8e308 gives the fallback, because every engine prints it as infinity. `NumberInput` now includes `string`; any string that is not a plain decimal still gives the fallback with a dev warning.

  Ranges are exact on every engine. V8's own `formatRange` rounds string ends to doubles, so `Intl` lays out a range only when the nearest doubles print exactly like the ends (every amount up to about 15 significant digits). Beyond that, the two exact ends are joined by the locale's range separator, without merging a shared currency sign or suffix. Ends that are numbers, bigints and decimal strings are ordered exactly.

  `formatCurrency(m, options?)` and `currencyFormatter(code)` take a Money (`{ amount, currency }`) and show it with its own digits, the same on every engine. A custom code such as `USDT` (2 to 12 upper-case letters or digits) is placed where the locale puts a currency code. It is always shown as the code, with 2 fraction digits for a plain value and the Money's own scale for a Money. An amount with more fraction digits than the engine supports gives the fallback with a dev warning instead of throwing.

  The docs now explain that `formatDateRange` uses the locale's CLDR interval data (Czech numeric ranges repeat the year), and that a conversion with `convertTo` is binary-float arithmetic and therefore not exact. A test checks that `formatDateRange` matches `Intl.DateTimeFormat#formatRange` across locales.

## 0.54.0

### Minor Changes

- [#4738](https://github.com/pyreon/pyreon/pull/4738) [`e8fedbe`](https://github.com/pyreon/pyreon/commit/e8fedbe3ad940127ec9337b73ec9be1d2a3c9a04) Thanks [@vitbokisch](https://github.com/vitbokisch)! - `@pyreon/format` now sits on `@pyreon/ambient`, and gains relative time that updates itself.

  - **One locale, one zone, one clock.** `locale`, `setLocale`, `provideLocale`, `timeZone`, `setTimeZone` and `provideTimeZone` are re-exported from `@pyreon/ambient` (a regular dependency of the reactive entry; `@pyreon/format/core` stays dependency-free), so an app with `@pyreon/format`, `@pyreon/time` and `@pyreon/ambient` has one locale, one time zone and one clock. Behaviour is unchanged.
  - **`useRelativeTime(target, options?)` and `<RelativeTime>`:** a relative label that keeps itself current. It updates at the moment the text changes (each second under a minute, at the target's own minute and hour marks, at local midnight once it counts days), every label on a page shares two timers, a server render starts none and hydrates without a mismatch with the clock hand-over, and `threshold: { after: { days: 7 }, as: 'medium' }` switches to an absolute date. `<RelativeTime>` renders `<time datetime title>` with the exact time on hover.
  - **`relativeFormatter` without a `base`** reads the ambient clock in the reactive entry (a plain `now()` per call); `@pyreon/format/core` still requires a base.
  - **A date-only target is that day in the display zone** in relative time (`formatRelativeTo`): at 10:00 in Tokyo, `2026-11-18` is "10 hours ago" instead of "1 hour ago", and from midnight on the 19th in Kiritimati it is "yesterday" instead of "10 hours ago". `@pyreon/time`'s `relativeDistance` gives the same words; both packages test one shared table.
  - **`@pyreon/ambient`:** `useNow({ every })` accepts a function returning `{ at: instant }` for one update at an exact instant, then reads the function again. Readers that each want their own instant share ONE timer. A function `every` is also read again after every update of the ticker the reader holds. `_resetLocaleState` also forgets printed warnings.
  - Fix: `relativeFormatter({ style })` (and `formatRelative`/`formatRelativeTo` options with only `style`) kept `numeric: 'always'` instead of the `auto` default.

- [#4738](https://github.com/pyreon/pyreon/pull/4738) [`e8fedbe`](https://github.com/pyreon/pyreon/commit/e8fedbe3ad940127ec9337b73ec9be1d2a3c9a04) Thanks [@vitbokisch](https://github.com/vitbokisch)! - New package `@pyreon/format` (Experimental): locale-aware formatting and parsing as plain functions over `Intl`.

  - **Formatters:** `formatNumber`, `formatCurrency`, `formatPercent`, `formatCompact`, `formatUnit`, `formatBytes` (decimal `1.5 kB` or binary `1.5 KiB`, never `1000 kB`), `formatDuration` (`Intl.DurationFormat` with an equivalent fallback; `long`, `short`, `narrow`, `digital`), `formatList`, `formatDate`, `formatTime`, `formatDateTime`, `formatRelative`, `formatRelativeTo`, `formatDateRange`, `formatNumberRange`, `formatNumberToParts`, `formatDateToParts`.
  - **Parsers:** `parseNumber` (the locale's digits, separators and typed variants; `null` for anything else) and `parseDate` (numeric dates in the locale's order, impossible dates rejected, a stated two-digit-year rule).
  - **Reactive without ceremony:** `@pyreon/format` reads the active locale and time zone (`locale`, `setLocale`, `provideLocale`, `timeZone`, `setTimeZone`, `provideTimeZone`), so a formatter in an effect, computed or JSX binding updates when they change. `provideLocale` is request-scoped on the server.
  - **Calendar dates never shift:** a date-only string (`2026-11-18`) or a date-time without offset formats as that day or wall-clock time in every time zone.
  - **Never throws on data:** nullish input returns the `fallback`; invalid input returns it with a dev-only `[Pyreon]` warning. A bad option or unknown unit throws a `[Pyreon]` error that says how to fix it.
  - **Cached:** every `Intl.*Format` is cached in three bounded tiers (no options, preset string, options object by identity then structural key).
  - **Entries:** `@pyreon/format/core` (pure, no `@pyreon/*` import), `@pyreon/format` (reactive, plus `defineFormats`) and `@pyreon/format/components` (`<Num>`, `<DateTime>`).
  - **Composable formatters:** one exported factory per kind (`numberFormatter`, `currencyFormatter`, `percentFormatter`, `compactFormatter`, `unitFormatter`, `bytesFormatter`, `durationFormatter`, `listFormatter`, `dateFormatter`, `timeFormatter`, `dateTimeFormatter`, `relativeFormatter`). A `Formatter` is a plain `(value) => string` (so it works as a callback) with `with(overrides)`, `from(map)`, `fallback(text)`, `options`, and `parts` / `range` where `Intl` has them. `<Num>` and `<DateTime>` accept `format={formatter}` and a typed `parts` map to wrap a part.
  - `defineFormats` names a format set; each key is a real `Formatter`, and a spec may `extends` another by name. `createFormatter` gives a bound non-reactive set of one-off functions for servers, scripts and tests.
  - **Behaviour found by hands-on review:** bytes below a kilobyte use the symbol in the locale's own kilobyte pattern (`0 B`, `999 B`), and continue to EB/ZB/YB and EiB/ZiB/YiB above petabytes; `formatDuration` balances fractional fields (`{ hours: 1.5 }` is `1 hr, 30 min`), rounds to seconds from one second on with carries, takes `smallest`, and its digital style is `h:mm:ss`; `formatTime` accepts a time of day (`14:30`); date and number ranges are ordered when reversed; `formatRelativeTo` counts calendar days, months and years from 24 hours on, so "yesterday" and "last month" are literally true; an invalid `timeZone` warns once and falls back to the active zone; `signDisplay` defaults to `'negative'` so `-0` prints `0`; no raw platform error reaches the caller (a fuzz test covers every function).
  - **Parsing what people type:** `parseNumber` accepts a numpad `.` in comma locales that do not group with a dot; new `parseCurrency`; `parseDate` reads the locale's own medium and long forms with month names.
  - **Components:** `<DateTime>` sets `title` to the exact date and time and isolates bidi text; `<Num>` takes `tabular`, `isolate` and forwards `class` and other props; `<DateTime format>` accepts a relative formatter.
  - **Install shape:** `@pyreon/core` and `@pyreon/reactivity` are REQUIRED peers (the reactive entry and the components import them); `@pyreon/format/core` imports no `@pyreon/*` package. `exactTitle`, `machineValue` and `partsToChildren` are internal, not exports of the components entry.

- [#4738](https://github.com/pyreon/pyreon/pull/4738) [`e8fedbe`](https://github.com/pyreon/pyreon/commit/e8fedbe3ad940127ec9337b73ec9be1d2a3c9a04) Thanks [@vitbokisch](https://github.com/vitbokisch)! - Unit conversion in its own entry, `@pyreon/format/units` (and `@pyreon/format/units/core`, pure), so an app that never converts pays nothing.

  - **`convert(value, from, to)`, `canConvert`, `unitDimension`:** between the units `Intl` can format, with `-per-` compounds (`kilometer-per-hour` to `mile-per-hour`). Every factor is an exact definition (inch = 25.4 mm, pound = 0.45359237 kg, US gallon = 231 cubic inches), held as a rational and applied once, so a result is as accurate as one multiply and one divide allow. Temperature is affine, a fuel economy and its inverse (`mile-per-gallon`, `liter-per-kilometer`) are reciprocals, `month` and `year` have no fixed length, a mismatch throws a `[Pyreon]` error naming both dimensions.
  - **`measurementSystem(locale?)`, `preferredUnit(unit, locale?)`:** `us`, `uk` or `metric` from the locale's region (CLDR `measurementData`), and the unit a person there reads.
  - **`formatUnit` and `unitFormatter` with `{ convertTo, system }`:** convert, then format; `system: 'auto'` follows the active locale in the reactive entry.
  - `gallon` and `fluid-ounce` are the US units; a kilobyte is 1000 bytes.
